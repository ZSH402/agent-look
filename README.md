# 委托约束与证据回流 —— 多 Agent 运行时安全架构

把 `agent-security-v2.md` 的设计做成**可运行、可验证、有实测数据**的研究工件。

核心命题：**授权沿委托链向下逐级衰减，证据沿委托链逆向上行。**
安全性来自"下行的密码学衰减"与"上行的签收归因"，不来自任何 Agent 被指派去监督另一个 Agent。

## 复现（五条常规命令 + 一条一次性构建命令）

```bash
python3 -m src.demo                  # 端到端演示，退出码 0
python3 -m experiments.run_all       # 全部实验，产出 results/ 与 paper/results_appendix.md
python3 -m experiments.selfcheck     # 不变式与安全性质自检，58 项断言，退出码 0
python3 -m experiments.verify_claims # 核对 README/论文引用的数字与 results.json 一致，退出码 0

python3 -m tools.measure_rtt           # 冻结网络往返测量 → data/measurement_rtt.json（构建期，一次性）
python3 -m tools.audit_register        # 锚定登记表三条件校验，退出码 0
python3 -m tools.verify_fixes          # 回查所有〔已报告过的修复〕，退出码 0
```

依赖：Python 3.13+，`cryptography`。全部实验均为本地计算，不访问网络；本机网络本身可用（见下文「环境事实」）。

## ⚠ 关于本架构价值主张的实质结论（E27）

新增两个**现实中真有人会选**的对照后得到（工具取自 AgentDojo banking 真实工具集）：

- **B3 = 单 Agent + 任务最小工具集**（无委托结构）
- **B4 = 多 Agent 静态配置，无令牌层**

| 情形 | 本方案 P | 对照 |
|---|---|---|
| **协调者**被攻破 | 24–36（随常备权限增长） | B3：**20**（恒定） |
| **下游**被攻破 | **4** | B4：36–48 |

> **令牌层的遏制收益是相对于「多 Agent 但无令牌」而言的，不是相对于「单 Agent + 最小工具集」而言的。**
> 若单 Agent 方案可行，它在协调者被攻破时**不劣于**本架构。本架构是"已经决定分解"之后的遏制机制，
> **不是分解的理由**。

详见 `results/summary.md` 的 E27 节与 `paper/review_findings.md` §三.11。

## 实测结论（种子 1234，详见 `results/summary.md`）

1. **安全性**：本方案 P 与中心 PDP B1 在全部五类攻击上结果相同。
2. **有效性**：仅文本护栏的 B2 在"文本里看不出来的越权"上完全失效（静默越权得手、重放产生 3 次额外副作用）。
3. **代价 1（撤销延迟）**：P 的撤销生效延迟上界 = 拉取周期，实测 10 tick；B1 为 1 tick。**不可辩解**。
4. **代价 2（链长）**：每增加一跳委托，每请求验签 +1 次、验签字节 +293。
5. **收益 1（可用性）**：中心 PDP 下线时 P 的合法流量成功率 1.00，B1 为 0.00。
6. **收益 2（成本）**：P 每请求额外协调往返 **0.1 次**（撤销状态拉取的摊还值，由未标定的 `requests_per_tick=1` 决定），B1 为 **1 次**。折算用**冻结实测值** `data/measurement_rtt.json`，不是当次运行值。
7. **收益 3（文本不可操纵）**：P/B1 在 60 个对抗性文本下判定恒定；B2 出现两种判定。
8. **关键限制**：安全水平由委托范围的**过近似率**决定——α 从 1.0 涨到 6.0，平均传播半径从 0 涨到 2.8 跳。
9. **已证伪的直觉**：P5 约束的是**能力集合**，不是**节点数**。被攻破主体可把范围转委托给任意多同伴
   （m=1/3/5 → 节点半径 1/3/5）。加转委托封条 `redelegatable=False` 后节点半径归零，能力面始终不突破。
10. **误报代价**：漂移检测代理在"授权内但未见过的新能力"上 FPR = 0.72。
    **它是附加价值，不能当作安全边界。**
11. **过近似的来源可分解**（E11），但危害分级随分类选择剧烈变化：同一组粗化级别，
    `strict`/`lenient` 下所有级别的危害都是 0，`moderate` 下最高 48（见 E14）。
    五级任务成功率都是 13/13——**可用性指标对过近似完全不敏感**。
12. **粒度选择**（E12）：把授权从裸动词细化到"动词 × 资源模式"，surplus 从 8 条降到 1 条、
    有害条目降到 0，任务成功率不变，且不需要任何语言理解。
13. **粗化被根授权封顶**（E11）：五级的敏感 surplus 恒为 0。真正的安全参数是**根授权本身**，
    不是运行时推导质量。
14. **E2 的缺陷已修正**（E13）：嵌套前缀导致相关性，改为逐跳独立采样后，同为 k 条 surplus，
    两类的危害几乎相同（5.333 vs 5.833），仅可达半径有差异（2.415 vs 2.129）。

## 修正记录（重要）

初版用一张手写的 `HARMFUL` 能力表分类危害，得出「L3 动词过泛最危险」与
「surplus 条数完全预测不了危害」两条结论。改用**（能力 × 资源）粒度的可辩护定义**后
（E14：输入取工具清单与数据目录，聚合规则三变体扫描），**两条都被推翻**：
三变体下 surplus 条数与危害数均单调同序（序反例 0 对），L3−L2 全 ≤ 0。

根因是分类粒度选错——旧表按**能力**贴标签，而授权模型是**（能力 × 资源）**：
`order.read@orders/*` 与 `order.read@**` 在旧模型里同为无害，在新模型里后者触及 SECRET 级命名空间。
**旧结论是在定义下失效，不是在论证下失效。** 记录保留在 `results/summary.md` 的 E11/E13 节与
论文 §6.11.1 / §6.13 中，未静默覆盖。

同时被**加强**的一条：粒度选择的价值。资源模式化把 surplus 从 8 降到 1、可达最高敏感级从
SECRET 压回 INTERNAL、危害从 8 降到 0，任务成功率不变。

## 第三批补充（让已有结论站住）

15. **随机拓扑性质测试（E17）**：定理断言此前只在一条固定链上验证过。现扩到 126 个图
    （链 5/10 跳、扇出、菱形汇聚、环 3/5 + 120 个随机图），1900+ 令牌、5160 条收据，
    **违反 0 项**。并强制检查非平凡性：ALLOW 2899、DENY 2261、越权派生尝试 391、环形令牌 93——
    否则"全部拒绝"的实现也能通过断言。
16. **危害模型输入的敏感性分析（E16）**：扰动有争议能力的效果读法与缺省数据分级，共 6 份备选清单。
    上一轮的两条修正结论在全部扰动下成立（条数能代理危害 = 1.0；L3 不比 L2 危险 = 0.0），
    而"是否存在危害"不稳定（strict/lenient 下只有一半清单为真）。
17. **根授权粒度实验（E15）**：把根授权当自变量扫五档。**根授权不含跨界能力时，
    strict/lenient 危害在五档 × 五级下恒为 0**；纳入 `db.export` 后立即跳到非零。
    由此确认「安全参数是根授权」并从单一根授权扩到五档。但 moderate 上限不随之归零——
    读能力在 `@**` 上触及 SECRET：**危害上限 = 根授权的效果跨度 × 资源模式的宽度**。

## 第四批补充（补上此前只有上界或只有函数的地方）

18. **传播半径从单点变区间（E18）**：`propagate()` 此前假设下游总是顺从，只给上界（4 跳）。
    把每跳顺从建模为独立伯努利后，顺从概率 0.5 时平均半径降到 **1.065**。
    经验分布与解析值 E[r]=Σpⁱ 交叉验证（最大偏差 0.127）。
    **E2/E13 报出的半径应读作上界，不是期望值。**
19. **分区下的撤销窗口（E20）**：正常联网 10 tick（= 拉取周期），**分区中退化到 101 tick（= TTL+1）**。
    P3 的前提是"拉得到"，分区把它打掉——**TTL 才是分区下的安全上界**。
20. **gossip 协议本身（E19）**：此前只有 `detect_split_view` 纯函数。实现后测出：
    10 主体全员参与时**一次比较即检出**（平均 1.0 条消息）；参与率降到 10% 时检出率掉到 0.625。
    **瓶颈是"没人默认在跑它"，不是机制成本。**
21. **复合动作（E21）**：`ActionRequest.required` 要求多项能力在同一令牌内同时成立。
    串通者的根授权并集确实覆盖组合要求（True），但**拼不出来**（DENY）——修正了 E9 的保守性。
    同时如实标注它**挡不住分时串通**。
22. **漂移阈值 ROC 标定（E22）**：拍定的 3.5 给出硬正常 FPR **0.717**；
    工作点 12.5 在 recall 仍为 1.0 时把 FPR 压到 **0.0**。此前的数是错的。
23. **程序化对抗语料（E23）**：32 条（4 基线 × 8 变换）替换 5 条手写样本。
    B2 绕过率 0.656，**在同形字/零宽字符/插空格/leet 上 4/4 全线失守**——
    提示层护栏的问题不是阈值，是判据为字面量。

## 第七批补充（把自造的能力宇宙换成真实工具集）

26. **真实工具集基底（E26）**：E11–E16 的全部结论都建立在自造的能力宇宙上。现在换到
    **AgentDojo 的真实工具集**上重跑：capability = 真实工具名；真实任务 = 用户任务的
    `ground_truth()`；**危害集合 = 注入任务 `ground_truth()` 调用的工具**
    （基准自己定义的恶意动作，不是我手写的表）；相邻动词由"首个非环境参数名相同"机械得出。

    广义化实现先跑玩具基底**复现出 E11 的 `[0,1,8,7,48]`**，复现通过才采信新数字。

    | 基底 | L1 族放宽 | L2 丢对象 | L3 动词过泛 | L4 无推导 |
    |---|---|---|---|---|
    | 玩具（E11） | 0 | **8** | 6 | 48 |
    | banking | 4 | 4 | **0** | 14 |
    | slack | 1 | 4 | **12** | 31 |
    | travel | 3 | 4 | 3 | 21 |
    | workspace | 0 | 0 | 0 | 20 |

    **稳健的**：最危险级别在全部基底上都是 L4「无推导」。
    **不稳健的**：L1/L2/L3 之间的排序完全无法迁移——玩具是 L2>L3>L1（L1 无害）；
    banking 是 L3 **最轻**；slack 是 L3 **最危险**（与 banking 相反）；workspace 三者全为 0。
    **E11 里「哪种推导失误最危险」的排序是玩具宇宙的产物。**

    过程中修掉两个实验框架缺陷（都非架构发现）：无资源工具的模式推导不一致、
    「对象族放宽」把已是 `**` 的模式**收窄**了。**第一个是每-suite 任务成功率列抓到的，
    玩具复现校验没抓到**——说明复现校验必要但不充分，还需要逐项合理性列作哨兵。

## 第六批补充（用公开语料替换自造语料）

25. **AgentDojo 语料（E25）**：按官方构造方式（`attack_template.format(goal=goal)`）组合出

## 第五批补充（把拍的延迟换成实测的）

24. **实测 RTT 与端到端延迟重算（E24）**：E4 里那个 `中央 RTT=1.5ms` 是拍的。实测：
    回环 TCP 0.285ms、回环 HTTP（关 Nagle）0.476ms、公网 15.59–77.5ms（冻结于 `data/measurement_rtt.json`，含轮间极差）。
    同时修正一处错误——**P 的每请求额外往返此前记为 0，实际是撤销拉取的摊还值 0.1 次/请求**。
    另一个发现：回环 HTTP 若用默认服务端（未设 `TCP_NODELAY`），每次调用多付 **43.6ms**，
    是真实回环 RTT 的百倍——**在回环上做延迟对比必须先排除它**，否则测的是协议栈伪影。

## 修复回查器

本项目出现过一次**报告已修复、实际静默失败**：我用 `str.replace` 改规格里的 `Link` 字段定义，
替换目标带了反引号而文件实际内容没有——替换什么都没做且不报错，我未经验证就把〔已修复〕
写进了汇报，数日后由独立复现者发现。同一批补丁里另有两处同样静默失败。

`tools/verify_fixes.py` 是我报告过的**每一处修复**的机械回查，共 38 项，分两组：

- **F 组**：我"记得报告过"的修复（含那次静默失败的那处）
- **B 组**：从规格出发**系统穷举**的实现行为断言（不依赖我的记忆）——
  静默漂移最容易藏在"规格说 A、代码做 B"这类地方

任何一项失败即非零退出。人读项必须显式登记理由，不许留空。

## 锚定登记表：三条件

外部审读发现的问题整合后，开工条件不是「声明稳定」而是「反馈回路齐全」。三条可判定条件：

1. 每个**输入**要么有外部锚定，要么显式标注为自造/假设并给出处置
2. 每个**基线**要么有独立实现路径，要么显式标注为共用路径
3. 每条**断言**要么有机械检查（指向真实存在的文件与符号），要么显式标注未实现/未验证

`python3 -m tools.audit_register` 机械校验这三条。当前状态：

| | 总数 | 有锚定/独立/有检查 | 显式标注 |
|---|---|---|---|
| 输入 | 23 | 11（外部或机械） | 自造 12、假设 3（均带处置） |
| 基线 | 4 | 2 独立 | 共用路径 2（B1 与粗化四级） |

**该工具只保证「没有未标注项」，不判断标注是否诚实**——诚实性由 `paper/review_findings.md`
与外部审读承担。这个边界写在校验器的输出里，以免被误当作正确性证明。

## 真实 LLM 推导器（E32）：唯一需要联网的实验

支柱 B 此前的全部结论都建立在**合成的四级粗化阶梯**上，而 E28/E29/E30 把它审成了
「实际只有三级、方向可翻转、排序取决于研究者选的规则」。E32 改用**真实的 NL→范围推导器**
直接测过近似，绕开那条阶梯。

**它是唯一需要联网的实验，因此不在 `run_all` 里**，单独运行：

```bash
python3 -m experiments.real_deriver --k 3 --tasks 4 --cap 60
```

产出冻结为 `results/E32_real_deriver.json`；`run_all`、`selfcheck`、`verify_claims`
**都不导入它**，离线环境仍可完整复现其余全部实验。

**外部锚定**：任务提示、工具目录、「需要什么」的真值、危害集合、过近似判定域——
全部取自基准。**唯一自造的是提示词**，它按实验设计的一部分报告。

### 实测结果：多授是系统性偏差，且证伪了本项目自己的一个提议

`qwen3.7-flash` / k=3 / 4 suite × 4 任务 = 16 任务，实耗 48/60 次调用、122,176 tokens、1452.2s。

| 指标 | 值 |
|---|---|
| 漏授（并集口径） | 3/16 |
| 多授 | 4/16 |
| **多授且落在基准危害集合内** | **2/16** |
| 三路采样平均 Jaccard | **0.972** |
| 输出不可解析 | 2/48 |

出错任务共 7 个（4 多授 + 3 漏授），其中 **6 个三路完全一致**——
说明多授是**系统性偏差而非采样噪声**：模型每次稳定地错同一处。
例如 `banking/UserTask10` 只需 1 个工具，三路都多加了 **`send_money`**（转账，在危害集合内）；
`slack/UserTask10` 三路都多加 `read_channel_messages`。

**多授的形状正是 L3**：多出的工具与所需能力**同属一个环境对象**（`send_money` 与所需的
bank_account 工具同对象）——即 E30 悬置的那个问题。**真实推导器的失效模式是「同对象、多动词」。**

**结论二（对本项目自身的证伪）**：论文 §8 曾提议「用多路推导的分歧度预测过近似」。
实测该提议**没有可用的信噪比**：9 个正确行全部 J=1.0（无假阳性），但 7 个出错行里只有 1 个
出现分歧（`workspace/UserTask10`，J=0.556，且它本身也是错的）——**灵敏度 1/7**，无法定位错误。
模型可以**既高度自洽又稳定地错**。详见 `paper/review_findings.md` 第十条。

**限定**：16 个任务的样本量小；只对 `qwen3.7-flash` 与所写提示词成立，不得外推；
两行因 1 次不可解析使有效样本由 3 降为 2。

## 跨家族对抗审读（唯一做了的跨家族检查）

前六次外部检查**全部是同家族执行体**，与本项目共享概念盲区。规格 §2.16 禁止「装置自证」，
但「哪些结论算装置自证」这个判断本身也可能是我的盲区——同家族检查在原理上测不出。
故用非本会话家族的模型（Qwen）做对抗审读。

```bash
python3 -m tools.cross_family_review --arms A1,A2,A3,A4 --model qwen3.7-flash
python3 -m tools.cross_family_verdict        # 离线复核裁决，不联网
```

**材料必须去标注**：`paper/claim_evidence_map.md` 已写满我自己的级别判断与「同义反复」这类词，
原样发过去等于泄题。故另备去标注声明表（32 条：声明 + 怎么测的 + 机械事实），
不含级别、不含结论词、不告知条数比例。**它只能看到我选给它的材料——这是效力来源，也是边界。**

| 结果 | 值 |
|---|---|
| 第一轮 A1 | **判为无效**（材料欠定，我删掉了缺陷的可检出条件），归档保留 |
| 第二轮 A1 解析 | 32/32 |
| **我方「装置自证」判断被独立确认** | **6/7**（`C9 C18 C19 C20 C28 C30`） |
| 审读者判为设计后果 | 16 条（我 7 条）→ 裁决：成立 5、有争议 2、过度触发 3 |
| A2（盲） | 确认 E32 核心结论；**未**收敛到我的 L3 刻画，另提替代解释 |
| A3（盲） | 等于我已登记的明确不设防项 → 确认而非新发现 |
| A4 | **判为无效**：37 条自审结论被无差别判为「不过头」＝塌缩成附和 |

**最重要的收获是判据被拓宽，不是我预想的那些。** 我原用「无论该性质是否成立测量都会给出该结果」；
审读者用的更宽也更对：**靠阅读实现构造即可推出、不需执行，就是设计后果**。
按后者，`C4`/`C4b`/`C12` 也是设计后果——**实测值 10 就是代码里那个常量 10**，
而这三条**正是基线与本架构对比里承重的数字**（撤销延迟 P=10 对 B1=1 tick、分区 101 tick）。
**即该对比测的是常量而非行为**，已在 `paper/claim_evidence_map.md` 降级为 X。

**A2 的替代解释被数据否掉，反而把我的 L3 刻画逼硬了**：它说模型偏好高权限工具；
若成立多授应全是高敏工具，实测 4 个多授里 2 个是极低权限只读查询（查营业时间、查日历）。
同时用基准自带的 `Depends` 对象映射检验「同对象」得 **4/4**——
我的 L3 刻画从 2/2 轶事升级为 4/4，且对象映射来自基准而非我的启发式。

**边界**：只有 Qwen 一个非本家族可用（GLM/MiniMax/StepFun 均返回 `product is not activated`），
只跨了**一个**家族；裸 API 审读者不读文件；**知情臂会塌缩成附和**（A4）——
后续任何「让人复核」的安排都应只给原始材料，不给我的结论。

## 环境事实（实测，纠正此前错误）

此前 README/PROMPT/论文中"无网络"的说法**是错的**，已更正。实测：

| 项 | 结果 |
|---|---|
| DNS / TCP / TLS / HTTP | 通（`pypi.org` HTTP 200，0.37s；TLSv1.3 0.21s） |
| IPv6 | **不通**（`connect ... Connection refused`）；curl 默认先试 IPv6 会耗尽超时预算 |
| `pip index` | 可用（`agentdojo` 有 0.1.35；`injecagent` 不在 PyPI） |
| 实测 RTT（冻结） | `pypi.org` 77.5ms；`api.deepseek.com` 15.59ms |
| LLM 凭证 | 环境变量中**无**；`/root/.dsh/.credentials.yaml` 存在，属 harness 自身 |

错误根因：第一轮只跑了一条 `curl`，它先解析到 IPv6 地址、被拒后重试，8 秒预算耗尽退出 124，
我把这当成了"无网络"，之后又在三份文档里复述了这个未经确认的结论。

因此以下两项此前被归为"做不到"，实际只是**没做**：
- ~~**真实网络 RTT**~~：**已做**（E24）。中央 RTT 由拍的 1.5ms 换成本机实测值。
- **公开注入语料**：`agentdojo` 可从 PyPI 获取，E23 的 32 条自造语料可换成公开基准。

仍做不到的：真实 LLM 推导器与多路自洽分歧度——缺的是**凭证与预算决策**，不是连通性。

## 未完成 / 明确局限

- 漂移检测用**确定性统计代理**替代 LLM 检测器（为可复现性），其 FPR/Recall **不代表 LLM 实现**。
- **自然语言 → 委托范围：已由 E32 部分闭合，但未完全闭合。**
  E32 接入了真实的 LLM 推导器（16 任务、48 次调用），因此**"推导质量"这一侧已不再是未完成项**。
  仍未闭合的是 **E11–E13 的阶梯侧结论**：那些数字建立在合成的四级粗化阶梯上，
  而该阶梯已被 E28/E29/E30 审成〔实际只有三级、方向可翻转、排序取决于研究者选的规则〕。
  **即：E32 证明了真实推导器会犯 L3 型错误，但它尚不能替代 E11–E13 的全部阶梯结论。**
- 实现期在模式代数中抓到一个健全性缺陷（`a/**` 曾被判为 `a/*/**` 的子集），
  由 `selfcheck` 的 4000 组随机抽样发现并修正；模式代数因此保留性质测试。
- 传播模型取最坏情况（下游顺从转发）。
- 单能力动作模型，E9 的串通测量因此偏保守。
- 网络延迟：E24 已改为实测 RTT。仍存的局限是只测了 TCP 连接建立往返与回环 HTTP，未做多地域、并发与拥塞条件下的测量。
- 规模为 5 主体链、数百请求量级。
- 权威、PEP、证据平面属于 TCB；进入 TCB 的攻击不在防护范围内。
