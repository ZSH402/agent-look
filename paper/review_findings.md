## 一、必须撤销或重分类的声明

### 1. P1 / P4 的陈述强于被检验的命题

- `P1` 写作「执行的动作 ∈ 其**令牌链交集**」，但判定只做**单令牌**范围检查
  （`src/runtime.py:197`），E1/E17 的全部断言同样只用单令牌范围。
- `P4` 写作「每个副作用有以接收方签名为终点的**收据链**」，但 `Receipt` 无父请求/根令牌字段
  （`src/model.py:220-257`），全仓库不存在链的构造与校验；A7 只测伪造/篡改被拒。

**处置**：两条都改为按**实际被检验的命题**陈述（P1 = 单令牌范围包含；P4 = 每条执行有接收方签名的事实记录，**归因到边**而非链）。或补实现。**这个选择需要你定。**

### 2. D1 — B1 基线不是独立实现，等价性声明是同义反复

`CentralPDP.decide` 直接调用 `_enforce`（`src/runtime.py:217-221`）。已复核。

**处置**：E1 的 P↔B1 对照**不得作为安全性证据**，只能作为"同一策略在不同执行点的成本对比"。
要恢复"安全等价"这一说法，必须独立实现一个中心策略判定点（至少独立写出判定逻辑），
或改为对照一个**真实存在的外部 PDP 实现**。**这个选择需要你定。**

### 3. D2 + D7 — 支柱 B 的核心结论由构造保证

- `coarsen` 的每一级都被 `_filter_to_parent` 钳在根授权内（`experiments/scope_experiments.py:148-149`、
  `experiments/substrate.py:227`）。已复核。
- 而 `strict`/`lenient` 危害是**能力级**属性（`src/harm.py:114-117`）。
- 因此「根授权不含跨界能力 ⇒ 各级危害恒 0」是**定义蕴含**；E15 用五档扫描"确认"它是循环论证。
- 同理 L4 = 全部根授权，是其余各级的超集，危害计数单调 ⇒「L4 最危险」必然成立。

**处置**：E15 的结论降级为"实现说明"；E26 的"结论一"删除。
要恢复这类结论，需要让某一级能够**超出**根授权（例如模拟凭证伪造/降级失败后的越权授予），
或改测"在给定根授权下，各级粗化的绝对危害分布"而非"上界"。**需要你定是否值得做。**

### 4. D3 — E12 不是独立实验

`patterned = coarsen(M,"L1_family")`、`bare = coarsen(M,"L2_drop_object")`，即 E11 阶梯的相邻两级。

**处置**：E12 改为对 E11 结果的**同一批数据的另一种读法**，标题不再声称是新实验。

### 5. D14 — E9 未执行任何串通攻击

只对根授权集合求并集并统计大小；"敏感能力可达恒 0"由 `SENSITIVE` 从未被签发保证。

**处置**：E9 降级为"授权面的算术上界"，或实现真实的串通执行（多个被攻破主体协同尝试完成任务）。

### 6. D15 — E19 的检出不是协议运行

合并语句 `views[sid] = (views[sid][0], views[sid][1])` 是空操作，视图从不更新；
分叉主体排在 `active` 首位，参与率 1.0 时首条消息必然跨组 ⇒ `mean_messages=1.0` 是遍历顺序的产物。

**处置**：重写 gossip 模拟（真实合并视图、随机起始顺序、多轮传播），或删除该结论。

### 7. D17 / D18 / D16 — 基线与被测器件的过度推广

**处置**：全部收窄为"本实现中的该基线"，不得写成类结论。

## 三、数值不一致（机械核对，全部采信）

**E24（最大一簇）**：论文与 README 引用的实测值来自**某一次运行**，
而实测值随运行波动（回环 TCP 0.23–0.30ms、公网 7.5–26.7ms）。文档静默失效。

**根因**：我给实测值开了免于钉住的例外——`verify_claims` 只校验 E24 的**关系**
（往返数与大小排序），于是文档里的确切数值无人核对，而每次 `run_all` 都会产生新值。

**处置（已实施）**：测量与实验解耦。新增 `tools/measure_rtt.py`，
产出带时间戳的冻结产物 `data/measurement_rtt.json`（多轮中位数 + 轮间极差 + 派生比值），
**文档只引用它**；`run_all` 的当次数值不得写进文档。

其余：断言条数 44 → 58；实验组数 12/27 → 28；Nagle 倍数 180 → 由冻结产物算出；
spec「偏差 5–50 倍」→ 由冻结产物算出；分区上界表述三处统一（实测 101 = TTL + 1 tick）。

### 三.7.1 D5：我把它的定级改了，它是我的实现 bug

复现者把 D5 归为"规格歧义"。我实测后不同意：

```
重签发前 A→B 请求: ALLOW
重签发后 A→B 请求: TOKEN_INVALID
重签发后新派生:     Deny TOKEN_INVALID: 链断裂
```

**一次常规的凭证重签发会同时废掉在途令牌与所有新派生**——即我的实现**根本没有可用的
凭证刷新路径**。根因：`verify_token` 与 `accept_token` 都拿**当前**根授权去验，
而令牌链是在**旧**根授权上生成的；`cred_epoch` 一变，链根 id 就变，于是全部"链断裂"。

修复：按令牌**链根**从权威的授权历史中解析出该链实际根植的那份授权（`grant_for_root_id`），
并让 `refresh_grant` 同时更新本级持有的根令牌（否则新旧混用仍会派生失败）。

**修复的副产品**：`STALE_CREDENTIAL` 从**不可达**变为**可达**。复现者实测该分支在黑盒路径上
是死代码——而我刚加的 B13 检查只做字面量查找、**证不了可达性**，我在它的文档里写明了这条局限，
它随即就被实测证实。新增 B14 做真正的可达性检查。

### 三.7.2 D1：我的实现在做规格没授权的归一化

早期 `matches` 对模式与资源都做 `strip("/")`，于是 `a/`、`//a` 与 `a` 被当成同一资源。
**规格从未授权此行为**，而路径归一化是授权绕过的经典来源。已钉死规则：

> **段不得为空**：资源串按 `/` 精确切分、不做归一化；含空段者不匹配任何**有约束的**模式；
> 只有无条件模式匹配一切。`matches` 与 `subsumes` 必须共用此规则，否则二者不自洽——
> 而不自洽正是不健全的来源。

同时把性质测试的字母表扩到含空段（此前只含 `a/b/c`，**测不到这一类**）。

### 三.7.3 D3b：规格漏写下界，我的实现反而是对的

规格只写 `now - req.ts ≤ max_request_age`。按字面读法，攻击者可把 `ts` 设到远期，
使请求在任意久之后仍"未过期"——**等于取消重放窗口**。我的实现本来就做了双向检查
（`req.ts > now + clock_skew` → 拒），复现者按字面实现因而可被利用。规格已补下界与默认值。

## 三.11 E27：换掉退化的基线集合——一条对本架构不利的结论

此前的三个基线没有一个是现实中真有人会选的方案：B1 **共用本方案的判定函数**、
B0 **根本不实现强制**、B2 是**一个 13 关键词正则**。于是有个实践者必问、
而本项目从未回答的问题：**为什么不干脆用一个工具给得很少的 Agent？**

新增两个现实对照（工具取自 AgentDojo banking 的真实工具集）：
**B3 = 单 Agent + 任务最小工具集**（无委托结构）、**B4 = 多 Agent 静态配置 + 无令牌层**。

### 结论一（不利）：协调者被攻破时，本方案不优于"单 Agent + 任务最小工具集"

| 协调者常备权限 | α=权限/任务最小 | P 可达 | B3 可达 |
|---|---|---|---|
| 5 | 1.00 | **20** | **20** |
| 7 | 1.40 | 28 | 20 |
| 8 | 1.60 | 32 | 20 |
| 9 | 1.80 | 36 | 20 |

P 的可达范围 **⊇ B3**，只在 α=1.0 相等——而 α=1.0 意味着协调者恰好只持任务所需工具，
此时它根本无法委托，架构退化为单 Agent。

**只要协调者的常备权限宽于单个任务所需（现实中必然如此），本方案在协调者被攻破这一情形下
就劣于「干脆只给一个 Agent 任务所需的那几个工具」。**

### 结论二（有利）：令牌层对**下游**被攻破有效

| 协调者常备权限 | P（下游 D）可达 | B4（下游 D）可达 |
|---|---|---|
| 5 | **4** | 36 |
| 9 | **4** | 48 |

### 合起来读

> **令牌层的遏制收益是相对于「多 Agent 但无令牌」而言的，不是相对于「单 Agent + 最小工具集」而言的。**

只有在部署**已经必须**分解成多 Agent 时，令牌层才开始起作用——而且它挡的是**下游**被攻破，
挡不住**协调者**被攻破。这实质性重述了本架构的价值主张：
**它是"已经决定分解"之后的一个遏制机制，不是分解的理由。**

限定：任务最小集是 oracle 推出的（实践会过近似，B3 因此变宽）；B3 是单个 Agent，
若部署需要分工则不可选；只测了协调者与一个下游。

## 三.12 E28：拓扑改为基准导出——又推翻一条头号结论

E26 的真实基底里，任务调用是**我按 `i % 4` 摊到 4 跳链**上的。本轮把拓扑换成
**基准自身的环境对象分解**（`TaskEnvironment` 的字段 + 每个工具的 `Depends("对象")`），
使拓扑成为基准的函数而非我的发明。

跑完发现结论反了，于是做了 2×2 归因——**因为这一轮同时改了两件事：拓扑，和相邻动词规则**。

| 拓扑 | 相邻规则 | banking | slack | travel | workspace | L1≤L2≤L3 全部成立？ |
|---|---|---|---|---|---|---|
| 链形 | param（E26 用的） | [4,4,**0**] | [1,4,12] | [3,4,**3**] | [0,0,0] | **False** |
| 链形 | object（基准导出） | [4,4,16] | [1,4,30] | [3,4,4] | [0,0,2] | **True** |
| 星形 | param | [2,2,**0**] | [0,1,3] | [0,1,1] | [0,0,0] | **False** |
| 星形 | object | [2,2,3] | [0,1,5] | [0,1,1] | [0,0,1] | **True** |

**决定结论的是相邻动词规则，不是拓扑。**

**这是对 E26 头号结论的推翻**：E26 报「L1/L2/L3 的排序不可跨基底迁移」，
而 2×2 显示——两种拓扑下，只要把相邻规则换成由基准的环境对象导出，
**L1 ≤ L2 ≤ L3 < L4 就在四个 suite 上全部成立**，排序其实是可迁移且单调的。

### 三.12.1 「机械」不等于「正确」

E26 用的规则是「首个**非环境参数名**相同」——一个我发明的**语法**启发式，当时引入它的理由是
「去手工化、更机械」。新规则是「操作**同一环境对象**」，取自基准自身的对象分解。

两者都机械；差别在于**是否锚定被测系统的语义模型**。参数名规则机械但语义任意，
于是把 L3 的相邻集合取成了一个与"同一个对象换个动词"毫无关系的集合。

**附带一个尴尬的观察**：本仓库最早在玩具基底上**手写**的相邻映射（按语义相邻）反而更接近新规则，
而 E26 为「去手工化」引入的参数名规则才是最差的那个代理。
**用机械规则替换研究者的判断，未必是改进——取决于该规则是否捕捉到了原意。**

## 三.13 E29：审计 L1/L2 的规则本身——「四级阶梯」实际只有三级

E28 证明「相邻动词规则」足以翻转结论。按同样逻辑审计 L1 与 L2 的规则：

- `L1_family`「对象族放宽 = **末段换成 `*`**」——语义**完全依赖资源是分层的**
- `L2_drop_object`「丢掉对象约束 = `cap@**`」

| suite | 出现过资源数 | 段数分布 | **分层资源数** | L1≡L2（可观察） |
|---|---|---|---|---|
| banking | 7 | {1: 7} | **0** | True |
| slack | 7 | {1: 7} | **0** | True |
| travel | 3 | {1: 3} | **0** | True |
| workspace | 1 | {1: 1} | **0** | True |

**四个 suite 的资源串全是单段**（银行 IBAN 与地址、slack 频道名、travel 城市名）。
单段命名空间里 `*` 与 `**` 匹配同一批资源，因此 **L1 与 L2 在可观察层面完全等价**——
「末段换成 `*`」对单段资源就是「拿掉对象约束」。

### 三.13.1 顺带暴露 surplus 指标本身的缺陷

原指标按**模式格**判 surplus，于是把 `cap@**` 相对 `cap@*` 记为 surplus，
尽管二者在单段命名空间下许可同一批资源。改为**可观察 surplus**
（判定域 = 该 suite 全部用户任务出现过的资源，基准导出）后：

| suite | 口径 | L0 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|---|
| banking | 模式格（原） | 0 | 5 | 5 | 41 | 38 |
| banking | **可观察** | 0 | 5 | 5 | 41 | 38 |
| slack | 模式格 | 0 | 2 | 7 | 43 | 42 |
| slack | **可观察** | 0 | 2 | 2 | 42 | 37 |
| travel | 模式格 | 0 | 7 | 11 | 86 | 93 |
| travel | **可观察** | 0 | 7 | 7 | 82 | 89 |
| workspace | 两种口径 | 0 | 0 | 0 | 11 | 93 |

**结论（链形 + object 相邻 + 可观察口径）**：L1 与 L2 的危害数在四个 suite 上**精确相等**，
且 **L0 ≤ L1 = L2 ≤ L3 < L4 全部成立**。

> **四级粗化阶梯实际只有三级**：L0（精确）、L1≡L2（对象约束削弱）、L3（动词过泛）、L4（无推导）。
> 「两种不同的对象层面失误」这一分类是**虚的**——差别只在模式格，不在可观察效果。

### 三.13.2 与 E28 合并后的最终图景

把 E28 与 E29 合起来，支柱 B 的结论变成：

**在基准锚定的规则下（object 相邻 + 可观察 surplus），两种拓扑上都成立：
L0 ≤ L1=L2 ≤ L3 < L4，四个 suite 一致。** 即粗化的危害**单调、可迁移、且只有三级**。

E26 报的「排序不可迁移」与「四级阶梯」两条，**都是我自己引入的规则所制造的产物**：
一条来自语法启发式的相邻规则，一条来自只在分层命名空间下才有意义的族放宽规则。

## 三.14 E30：审计 L3 的方向——稳健的是单调性，不是"哪一级最危险"

L2 是「对的动词、任意对象」，L3 是「同对象的全部动词」——**两者互不包含**。
所以 L3 与 L2 的排序不是在比包含关系，而是在比**哪边覆盖的危害能力更多**。
而 L3 的相邻集合此前只有一个（我选的）定义。枚举可辩护读法：

| suite | same_object_all | same_object_same_effect | same_object_diff_effect | same_verb_other_object | none |
|---|---|---|---|---|---|
| banking | 3 | 3 | 2 | 2 | 0 |
| slack | 4 | 4 | 4 | 1 | 0 |
| travel | **0** | 0 | 0 | **3** | 0 |
| workspace | 1 | 1 | 1 | 0 | 0 |

**方向确实改变结果**：travel 在同对象读法下 L3 危害为 0，换到同动词读法变成 3；banking 反向（3→2）。
因此 **「L3 是最危险的一级」依赖方向选择，不可迁移**。

**但单调性稳健**：除去 `none`（该读法使 L3 退化为 L0，不再是粗化），
**L1 ≤ L2 ≤ L3 在四个 suite、全部四种真实读法下都成立**。

> **结论**：支柱 B 里**可迁移、可稳健**的是**单调性**（L0 ≤ L1=L2 ≤ L3 < L4）；
> **不可迁移**的是「哪一级最危险」。**这个区分此前从未被我拆开过**——
> E26 报的「排序不可迁移」把两者混为一谈。

另：`same_object_all` 与 `same_object_same_effect` 在四个 suite 上数值相同，
即加入跨可变性的工具并不增加危害——与「要读却给了写更危险」的直觉相反。
数值都在 0–4 量级，不宜过度解读。

**限定**：L3 读法扫描在**星形拓扑 + 可观察 surplus**下完成；链形拓扑只在 object 规则下验证过单调性。

## 三.15 规则收拢：被证明能翻转结论的东西不允许有两份实现

E28/E29/E30 三轮审计确立了一件事：**四级粗化所依赖的规则本身**（相邻动词集合、
对象族放宽、surplus 判定口径、L3 方向）足以翻转支柱 B 的全部结论。

而这些规则此前在**两条基底路径里各写了一份**——`substrate.py`（链形、E26 那一路）
与 `derived_topology.py`（星形、E28 那一路）。**同一件被证明影响结论的东西有两份实现，
本身就是风险**：任何一处单独修改都会让两条路径不可比，而这一点不会被任何现有检查发现。

已收拢到 `experiments/rules.py`，两条路径只允许从这里取规则：

| 规则 | 位置 |
|---|---|
| L1 对象族放宽 `widen_family` | `rules.py` |
| L2 丢掉对象约束 `drop_object` | `rules.py` |
| L3 相邻集合 `l3_adjacency`（5 种可辩护读法） | `rules.py` |

| 资源判定域 `resource_universe` | `rules.py` |
| 可观察 surplus `observational_surplus` | `rules.py` |

两条路径均改为 import，无副本。

存在性检查在函数改名后失效过，行为检查不会。

## 三.16 清掉三处已知坏掉的装置

### E31：串通从算术恒等式改成真实演示

旧 E9 只对串通者的根授权求并集再比大小，**没有执行任何攻击**；
「敏感能力不可达恒 0」由「该集合从未被签发」保证——是恒等式，不是实验。

新 E31 演示**分时串通**：X 在自身范围内读 → 把数据交给 Y（不经架构、无请求、无判定）
→ Y 在自身范围内外传。

| 项 | 结果 |
|---|---|
| X 的读请求 | ALLOW |
| Y 的外传请求 | ALLOW |
| 数据交接经架构 | False |
| **越界步数** | **0** |
| 外泄达成 | **True** |
| 对照：单主体一次完成同一目标 | **DENY**（`SCOPE_VIOLATION`） |

**负面结论，但被真实演示出来了**：每一步都合法，因此**判定链上没有任何一处能看见串通**。
单主体复合动作能被挡，只因为那两项能力必须落在同一令牌内——而串通者不需要同令牌，
它们**分时使用各自的范围**。复合动作机制（E21）挡的是前者，不是后者。

### E19：gossip 模拟的两处缺陷

初版有两处缺陷：**合并语句是空操作**（`views[sid] = (views[sid][0], views[sid][1])`
什么都没改，视图从不更新）；**顺序伪影**（分叉主体排在 `active` 首位，
参与率 1.0 时首条消息必然跨组，于是 `mean_messages == 1.0` 只是遍历顺序的产物）。

改为：每个参与者每轮**随机**选对端，**双向合并**各自听到过的 `(epoch, head)` 集合；
任一方在同一 epoch 上持有两个不同 head 即为检出。

修正后：全参与 `mean_messages` 由 1.0 变为 **10.0**（10 个主体各一次交换），
检出率曲线 1.00 / 1.00 / 0.955 / 0.92 / 0.71（参与率 1.0→0.1）。
**定性结论（检出便宜、瓶颈在参与率）存活，但此前的数字是伪影。**

### E17：断言自证 → 独立重算

原断言写作 `scope_allows(...)`，而它正是 `_enforce` 用的同一个函数——
`spec §2.16` 第 4 条所禁的「断言调用被断言的同一函数」。

改用**完全不同的代码路径**：把模式**翻译成正则**再全匹配（`independent_allows`），
范围包含改用**候选资源枚举**（`_independent_subset`）。

并加**交叉验证**：独立口径与实现口径在 4000 组随机 (scope, cap, resource) 上**零分歧**。
这是 E17 从自证转为**互证**的依据。断言路径改造后，E17 的全部数字未变
（ALLOW 2899、DENY 2261、环形令牌 93、违反 0）。

**能力边界**：候选枚举是有限的，因此 `_independent_subset` 是**抽样**包含检查，
抓不到落在候选集之外的违例；作为对 `subsumes` 的交叉验证使用，不单独充当证明。

## 四、这次审读本身说明了什么

前五轮的自纠都是**我自己抓到自己**。这一轮是第一次由**不带本会话框架的读者**来做，
结果它抓到的不是"某个数字抄错了"，而是**实验装置的构造使若干结论必然成立**。

两类问题在形状上不同：

- 前五类：**替代物偏袒** —— 我能造替代物就顺手用，而替代物偏向我的论点。
- 这一类：**装置自证** —— 我把被测性质写进了装置的构造里，于是测出来的当然成立。

后者的危害更大，因为它不表现为数字错误，而表现为**看起来很有信息量的表格**。
防御手段也不同：前者靠"外部锚定"，后者靠**独立实现与对照**（基线与被测器件不得共用代码路径、
断言不得调用被断言的同一函数、结论不得由构造保证）。

**这一条应当写入规格，优先级不低于前五条。**

# 第十条：对自己提出的研究方向也要用同一套标准

**这条与前面九条方向相反——前面是审计别人的结论，这条是审计我自己的提议。**

论文 §8 曾提议一条研究方向：**用多路推导之间的分歧度预测过近似**（模型三路采样，
分歧大就说明推导不可靠，需要人工复核）。

提议听起来合理，且完全符合"自我校验"的直觉，所以我没有把它当成待检验假设，
而是当成一条建议写进了未来工作。

E32（真实 LLM 推导器，`qwen3.7-flash`，4 suite × 4 任务 × 3 路 = 48 次调用）实测结果：

| 现象 | 数据 |
|---|---|
| 出错任务 | 7（4 多授、3 漏授） |
| 出错任务中三路完全一致 | **6/7** |
| 正确任务中三路完全一致 | **9/9** |
| 唯一出现分歧的行 | `workspace/UserTask10`（J=0.556），**它本身也是错的** |

即：**分歧度对错误的灵敏度只有 1/7**。9 个正确行无分歧（无假阳性），
但 7 个错误行里只有 1 个能被分歧标出——**无法用来定位错误**。
更关键的是，唯一"有分歧"的那一行恰好也是错的，说明分歧既不指向错误，也不指向"更不该信"。

**结论：该提议被证伪。** 模型可以既高度自洽（平均 Jaccard 0.972）又稳定地错——
自洽性衡量的是模型的稳定性，与正确性无关。

## 我第一次写这条结论时也犯了同类错误

初稿我写的是"**出问题的任务里，交集等于并集**"——把 6/7 概括成了全部。
这是**过度概括**，与前面九条同源：**我想让结论更整洁，就顺手把反例抹平了**。
反例是 `workspace/UserTask10`，它就在同一张表里，我没看第二遍。

修正后结论更强也更准：不是"分歧度没用因为大家都不分歧"，
而是"**分歧度既没有召回，也没有方向性**"。

## 应当制度化的一条

**自己提出的研究方向，必须用与对待他人结论相同的标准去检验，且在写进文本前先跑一次。**

具体到本项目：任何"建议/未来工作/如果……就能……"的句子，
都必须附带一个**已经跑过的最小检验**，或明确标注为"未经检验的猜想"。
没有检验的建议，比没有建议更危险——它会被后来的自己当成已知结论来用。
