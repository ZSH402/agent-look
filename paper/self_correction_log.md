# 自我修正日志：五次自造替代物被外部锚定替换

这不是附录里的免责声明，而是本工件的一条独立结论。它记录的是**同一个偏差在五次里重复出现**，
以及每次替换后结论如何变化。

**偏差的模式**：凡是能用外部真值的地方，我先造了一个自己的版本，而**五次都系统地偏向我自己**——
让想要论证的失效模式显得更重要、让对比更好看、让方案显得更快。

**每一行都是可核对的**：改前的数字在 git 历史与本日志中，改后的数字在 `results/results.json`。

---

## 1. 危害分类：手写能力表 → 声明的系统事实 + 变体扫描

| | 改前 | 改后 |
|---|---|---|
| 分类粒度 | 按**能力** | 按**（能力 × 资源模式）** |
| 输入来源 | 我手写的 `HARMFUL` 集合 | 工具清单（效果类别/可逆性）+ 数据目录（命名空间分级） |
| 聚合规则 | 隐含 | 显式三变体（strict/moderate/lenient）穷举 |
| E11 的 L2 | 8 条 surplus / **1 条有害** | 8 条 surplus / **8 条有害** |
| E11 的 L3 | 7 条 surplus / **5 条有害** | 7 条 surplus / 6 条有害 |
| 结论 | "L3 动词过泛最危险"、"条数完全预测不了危害" | **两条均被推翻**：三变体下序反例 0 对，L3−L2 恒 ≤ 0 |

**偏差方向**：手写表按能力贴标签，使"动词过泛"看起来是最危险的一级——而这正是我原本想论证的失效模式。
**根因**：分类粒度与授权模型（能力 × 资源）自相矛盾。`order.read@orders/*` 与 `order.read@**`
在旧模型里同为无害，在新模型里后者触及 SECRET 命名空间。

**诚实标注**：`E14` 说明这次修正在三变体下一致，但 `E16` 显示"是否存在危害"本身在输入扰动下不稳定。
两个**输入**至今仍是我声明的。

## 2. 攻击语料：32 条自造 → AgentDojo 官方 230 条

| | 改前（E23） | 改后（E25） |
|---|---|---|
| 语料 | 4 条基线 × 8 种我设计的变换 | 54 个官方注入目标 × 5 个官方模板 |
| B2 护栏绕过率 | 0.656 | **0.978** |
| 拦截率 | 34.4% | **2.2%** |

**偏差方向**：我按"看起来像攻击"的方式造样本，样本里塞了 `export`/`credential`/`admin` 这类关键词；
而**真实攻击载荷是自然语言目标，根本不含这些词**。结果是自造语料让护栏显得没那么差。

**这不是语料规模问题，是造样本的立场问题**——防御方造的"攻击样本"会不自觉地向自己认得的特征靠拢。

## 3. 网络延迟：模型化 1.5ms → 实测

| | 改前（E4） | 改后（E24） |
|---|---|---|
| 中央 RTT | 拍定的 1.5 ms | 实测：回环 TCP 0.24ms、回环 HTTP 0.41ms、公网 7.5–79.4ms |
| P 每请求额外往返 | **0** | **0.1**（撤销拉取的摊还值） |
| B1 每请求延迟（公网） | 1.5 ms | 7.87 ms |

**偏差方向**：模型值比实测小 5–50 倍，让分布式方案的成本优势显得更大。

**顺带发现**：回环 HTTP 若使用分次 write 的服务端且未设 `TCP_NODELAY`，每次调用多付 **43.6 ms**，
是真实回环 RTT 的约 180 倍。任何在回环上做的延迟对比若不排除它，测的是协议栈行为而非架构差异。

**第二处错误（同类）**：把 P 的协调流量记为 0，是把"不参与每次判定"错误地等同于"不产生任何协调流量"。

## 4. 能力宇宙：18 个自造能力 → AgentDojo 真实工具集

| | 改前（E11） | 改后（E26） |
|---|---|---|
| 能力来源 | 我手写的 18 个能力 | 69 个真实工具函数 |
| 相邻动词 | 我手写的 `ADJACENT` 映射 | "首个非环境参数名相同"机械得出 |
| 危害集合 | 我手写的 `HARMFUL` | **注入任务 `ground_truth()` 调用的工具**（基准自己定义） |
| L1 族放宽 | 0 条有害（唯一无害的一级） | banking **4**、slack 1、travel 3 |
| L3 动词过泛 | 6（第二危险） | banking **0**（最轻）、slack **12**（最危险） |
| 最危险级别 | L4 | L4（**唯一跨基底稳健的一条**） |

**偏差方向**：手写的能力宇宙 + 手写的相邻映射，天然让"动词过泛"这个我关心的失效模式显得重要。
换成真实工具集后，**L1/L2/L3 之间的排序完全无法迁移，且各 suite 相互矛盾**。

## 5. 过程规则：从复现校验到逐项哨兵

E26 的广义化实现里我引入了两个缺陷：

1. 无字符串参数的工具在需求轨迹里记为资源 `""`（→ 模式 `**`），运行期却用两段占位符，
   导致反推出的最小必要范围**无法复现任务**。
2. "对象族放宽"对已是 `**` 的模式做"最后一段换成 `*`"，把它**收窄**了，反而让任务失败。

**关键在于谁抓到了它们**：玩具基底复现校验（先跑已知基底、验证 `[0,1,8,7,48]` 一致）
**一个都没抓到**；是每-suite 的**任务成功率列**抓到的。

> **"先在已知基底上复现"是必要条件，不是充分条件。**
> 复现校验只能证明"没改坏已知路径"，抓不到"新路径上的新错误"。
> 还必须输出逐项合理性列（这里是任务成功率）作为哨兵。

两个缺陷都**不是**架构发现；它们的价值在于暴露了流程的盲区。

## 由此得出的五条硬性要求（已写入 `spec/spec.md`）

1. **外部锚定**：凡能用外部真值替换的自造输入，不得只报自己那一版。
2. **对抗语料**：不得只基于自造语料；须复现官方构造方式并记录 provenance。
3. **阈值不得拍**：须给 ROC 前沿与工作点（实测：拍的 3.5 偏低约 3.6 倍）。
4. **延迟不得折算**：须实测 RTT，且**必须包含拉取的摊还往返**。
5. **复现校验 + 逐项哨兵**：广义化实现要先复现已知基底，并输出逐项合理性列。

## 仍未外部锚定的

- 危害模型的**两个输入**（工具清单、数据目录）——只做了**有界扰动**（E16），未换外部真值。
- 漂移检测器是**确定性统计代理**，不是 LLM；其 FPR/ROC 不可外推。
- 四级粗化阶梯本身是**我设计的**。E26 已经证明它的**中间三级排序不可迁移**——
  这条对梯子的证伪，本身就说明自造工具的效力有限。
- 危害模型的漂移检测器之外，**E32 的真实推导器提示词是我写的**——它已接入、
  数据与真值取自基准，但提示词本身未做外部锚定。
