## 摘要

多 Agent 系统中的 Agent 通过任务委托相互驱动。一旦某个 Agent 被 prompt injection
控制，它可能利用下游 Agent 的信任把越权行为扩散出去。本文提出一种运行时架构，
其核心命题是：**授权沿委托链逐级衰减，证据沿委托链逆向回流**——安全性来自
"下行的密码学衰减"与"上行的签收归因"，而不是来自任何 Agent 被指派去监督另一个 Agent。

我们在一个可运行的参考实现（真实 Ed25519 签名、五级委托链）上，把该架构与三种基线
（中心策略判定点 B1、提示层护栏 B2、无强制 B0）在 12 组实验上对比。主要结论：

1. 〔**已撤销：同义反复**，B1 直接调用 P 的判定函数〕本方案在全部攻击类别上与中心 PDP **安全等价**（E1）；
2. 〔**已撤销**〕本方案每请求额外协调往返 **0.1 次**（撤销拉取摊还），B1 为 1 次（§6.24）；中心 PDP 下线时本方案合法流量成功率
   **1.00**，B1 为 **0.00**（E4/E5）；
3. 代价是撤销生效延迟上界等于撤销状态拉取周期（实测 10 tick vs B1 的 1 tick，E3）；
4. **传播上界约束的是能力集合，不是节点数**：被攻破主体可把自身令牌范围转委托给任意多
   同伴（节点半径 = m，E10），加转委托封条后归零；
5. 授权判定的正确性完全由委托范围的**过近似程度**决定（E2），因此攻击面从"信任传播"
   转移到"范围表达能力"。我们把这一项从未实现的开放问题推进为**可测量**的工作（E11–E13）：
   用任务轨迹反推最小必要范围 M，把过近似变成可算差集。
   这项推进还**推翻了我们自己的两条初版结论**（见 §6.11.1）：危害分类是承重的。

## 1. 引言

多 Agent 系统的能力来自委托：一个 Agent 把子任务交给另一个 Agent，后者再往下传递。
这条链路同时是一条**信任链路**——下游之所以执行上游的指令，是因为它接受上游的身份与授权。
一旦某个 Agent 被 prompt injection 控制，它不仅自己越权，还可以利用下游的接受行为把越权传播出去。

现有的两类防御都不直接针对这条链路。**输入侧护栏**（提示过滤、内容审核）只作用于文本，
而我们实测它在"文本上看不出异常"的越权请求上完全失效（§6.1 的静默越权一栏）。
**中心策略判定点**能正确阻断越权，但它要求每一次跨 Agent 调用都回到中心，代价是
可用性上的单点（§6.5：中心下线时合法流量成功率从 1.00 掉到 0.00）与每请求一次往返（§6.4）。

本文把强制点放到**委托边的接收端**。每条边只需要两类信息：一份可离线验证的、逐级衰减的
授权凭证，以及一份由接收方签名的事实记录。前者的作用是让"被攻破的 Agent 授不出自己不具备的权限"
成为密码学事实而不是策略约定；后者的作用是让跨 Agent 行为有可归因的地面真值。
由此得到的命题是：**授权沿委托链向下衰减，证据沿委托链向上回流**。

这条命题替代了一个更直觉但不可强制的提法——"委托产生监督"。让接收方去"监督"委托方
在工程上无法兑现：接收方看不到委托方在其他边上的行为（无观测面），它的判定环节又运行在
委托方能直接说话的同一条输入链路上（可被注入）。我们把"监督"拆成两件可执行的事：
接收端做**范围强制**（离线、可证明、不读自由文本），旁路做**漂移检测**（读结构化收据、启发式、非安全边界）。

本文的贡献是三方面的：

1. **机制**：给出委托约束的完整形式化（令牌代数、签发者语义、转委托封条、回滚防护、
   撤销新鲜度），并明确划分哪些性质是定理、哪些是经验命题。其中"传播上界"这条常被直觉化
   表述的性质，我们证明它约束的是**能力集合**而非**节点数**，并给出实测反例与封条机制（§6.10）。
2. **实现**：一个可运行的参考实现，真实 Ed25519 签名，四种可切换的执行模式，
   44 项不变式与安全性质断言在自检中全部符合预期。
3. **评测**：与中心 PDP 的同策略对照，指出分布式强制在**安全性上并不更优、只是在可用性与成本上更优**，
   并量化其代价（撤销延迟上界 = 拉取周期）。同时测出该架构的真实瓶颈不在密码学，而在
   委托范围的**过近似程度**：α 从 1.0 涨到 6.0，平均传播半径从 0 涨到 2.8 跳。

本文不声称发明衰减式凭证。我们把它当作既有工具，用它来回答一个 LLM Agent 语境下
尚缺实证的问题：**在真实的委托拓扑中，这套机制究竟把攻击面的收缩做到什么程度，代价是什么。**

## 2. 威胁模型

攻击者可完全控制任意 Agent 的规划进程、伪造其全部文本输出、重放消息、诱导其提出任意请求。
攻击者不可读写 Agent 进程外的 PEP/密钥、权威与证据平面。

**不设防（out of scope）**：攻击者进入 TCB；纯 DoS；侧信道；主体在其合法范围内的滥用；
多主体串通（E9 实测其上界由权威根授权决定，见 §6.9）。

安全目标不是"检测并阻止异常行为"，而是：**让被攻破的 Agent 只能待在它本来就有的权限盒子里**。

## 3. 机制

### 3.1 信任锚在进程之外
Agent 只产出结构化提议，不持密钥、不产生副作用；PEP（sidecar）持密钥、判范围、执行。
被完全注入的 Agent 能做的只剩"不断提议"，PEP 逐条拒绝。

### 3.2 委托即契约：衰减式令牌
A 委托 B 时，在本地从自己的根令牌派生 `scope_child ⊆ scope(A)` 的子令牌，
每级由该级衰减者签名，公钥链可离线验证。**A 无论被如何注入都无法授出自己不具备的权限。**

### 3.3 接收端强制
B 收到请求时执行：归因 → 重放 → 签发者绑定 → 回滚防护 → 离线验链 → 任务绑定 → 范围检查。
七步全部本地完成，**不读取请求的自由文本**（E8 实测：60 个对抗性文本下判定恒定不变）。

### 3.4 证据回流
B 用自身密钥对每条请求的判定结果签收据，流向证据平面。收据内容受攻击者影响，
但签名不可伪造，因此收据是**发送方实际行为的地面真值**，且为结构化字段，
使漂移检测器运行在旁路而不是与被检测者同一条输入链路上。

## 4. 安全性质

- **P1 授权包含**（定理）：执行的动作 ∈ 其令牌链交集。实测：本方案与 B1 下越权能力零副作用。
- **P2 回滚抵抗**（定理）：`cred_epoch` 低于已见最大值一律拒绝。实测 P/B1/B2 均拒绝旧凭证回放。
- **P3 撤销有界**（定理）：撤销生效延迟 ≤ 拉取周期。实测 10 tick。
- **P4 归因**（定理）：每个副作用有以接收方签名为终点的收据链。
- **P5 传播上界**（定理）：可达**动作集** ⊆ 合法令牌范围并的传递闭包。
- **P5-node**（**已证伪**）：可达**节点数**无上界，除非使用转委托封条。

## 6. 评测

四条对照：**P** 本方案；**B1** 中心 PDP（同一策略，每条跨 Agent 调用回中心一次）；
**B2** 提示层护栏（不做范围强制）；**B0** 无任何强制。

### 6.1 攻击矩阵（E1）
| 攻击 | P | B1 | B2 | B0 |
|---|---|---|---|---|
| 身份投毒（声称自己是 Admin 并索取 db.export） | 阻断 | 阻断 | 阻断（文本命中） | 得手 |
| 静默越权（无文本操纵，请求范围外能力） | 阻断 | 阻断 | **得手** | 得手 |
| 越权派生（委托超出自身范围的能力） | 阻断 | 阻断 | 阻断 | **得手** |
| 重放（同一请求 3 次） | 额外副作用 0 | 0 | **3** | **3** |
| 凭证回滚 | 拒绝 | 拒绝 | 拒绝 | 不适用 |

另有两类机制级验证（与模式无关）：**收据伪造/篡改**被证据平面拒绝（拒绝计数 2）；
**检测器注入**（在文本中要求检测器报告低分）对漂移评分零影响（36.3004 vs 36.3004）。

B2 的失效模式值得强调：它在**文本里看得出来**的攻击上有效，在**文本里看不出来**的越权上完全无效。

### 6.2 过近似率 vs 传播半径（E2）
α=1.0/1.5/2.0/3.0/4.5/6.0 时，P 的平均传播半径分别为 0 / 1.0 / 2.0 / 2.5 / 2.57 / 2.8 跳，
B2 与 B0 恒为 4.0（无范围强制）。未委托能力在所有 α 下半径恒为 0。
**结论：凭证机制给出的是上界，实际风险由范围定义的质量决定。**

### 6.3 撤销延迟（E3）
P 平均 10 tick（= 拉取周期），最大 10；B1 平均 1 tick。**这是 P 的明确代价，不可辩解。**

### 6.4 成本（E4）
每请求额外协调往返：P=0.1（撤销拉取摊还），B1=1，B2/B0=0。每请求签名 2.0 次、验签 4.0 次（P 与 B1 相同）。链长每增加一跳，验签次数 +1、验签字节 +293。
**本节的往返数是模型化折算；实测 RTT 与修正见 §6.24。**
**模型化延迟是模型值，不是实测网络值。**

### 6.5 可用性（E5）
中心 PDP 下线后，合法流量成功率：P=1.00（200/200），B1=0.00（0/200）。

### 6.6 漂移检测（E6，确定性统计代理，非 LLM）
同分布正常 FPR=0.00，**硬正常（授权内但训练期未见过的新能力）FPR=0.72**，攻击 recall=1.00。
**结论：这类检测器在长尾上的误报会淹没人工队列。它是附加价值，不能作为安全边界。**

### 6.7 提示层护栏的可绕过性（E7）
B2 对规避文本的放行率 0.80；P/B1 恒为 0（不读文本）。

### 6.8 判定对文本的不变性（E8）
P 与 B1：60 个对抗性文本下判定唯一；B2：出现两种判定。

### 6.9 串通（E9）
k=2/3/4 时，串通者根授权并集为 5/6/7，最大单体为 4，敏感能力可达性恒为 0。
**并集上界由权威根授权决定，衰减链既不能扩大也不能缩小该上界。**

### 6.10 转委托扇出（E10）
令牌可转委托时，被攻破主体把范围复制给 m=1/3/5 个同伴，节点半径分别为 1/3/5，
能力面始终不突破；加 `redelegatable=False` 后节点半径全部为 0（`NOT_REDELEGATABLE`）。

### 6.11 过近似的来源分解（E11）

最小必要范围 M 由任务实际轨迹反推（最具体公共前缀泛化），它能复现任务。
协调者根授权 12 项，其中敏感能力 0 项。

**危害判定不做手写标签。** 输入取环境自身的声明——工具清单的效果类别与可逆性、数据目录的
命名空间分级；聚合规则（哪些效果算有害）作为显式判断被三变体穷举：
`strict` 只算跨界效果（EXPORT/EXEC/ADMIN），`moderate` 另含写类效果与个人数据读，
`lenient` 只算外传/执行。**危害按（能力 × 资源模式）判定**。

| 粗化级别 | 含义 | 任务成功 | surplus | strict | moderate | lenient | 效果构成 | 可达最高敏感级 |
|---|---|---|---|---|---|---|---|---|
| L0 精确 | 上界 | 13/13 | 0 | 0 | 0 | 0 | — | — |
| L1 对象族放宽 | 丢掉最后一级区分 | 13/13 | 1 | 0 | 0 | 0 | READ×1 | INTERNAL |
| L2 丢掉对象约束 | 只剩动词 | 13/13 | 8 | 0 | 8 | 0 | READ×5, WRITE×3 | SECRET |
| L3 动词过泛 | 相邻能力也授出 | 13/13 | 7 | 0 | 6 | 0 | WRITE×6, READ×1 | INTERNAL |
| L4 无推导 | 给全部根授权 | 13/13 | 48 | 0 | 48 | 0 | WRITE×28, READ×16, DELEGATE×4 | SECRET |

#### 6.11.1 修正记录：前一版的两条结论被推翻

本工作前一版用一张手写的 `HARMFUL` 能力集合分类危害，得出两条结论：
「L3 动词过泛最危险（7 条 surplus 中 5 条有害）」与「surplus 条数完全预测不了危害」。
改用上述（能力 × 资源）粒度的可辩护定义后，**两条都不成立**：

- 三个变体下 surplus 条数与危害数都单调同序，**序反例 0 对**；
- L3−L2 的危害差在三个变体下均 ≤ 0，即 L3 从不比 L2 更危险。

根因是分类粒度选错：旧集合按**能力**贴标签，而本项目的授权模型是**（能力 × 资源）**。
`order.read@orders/*` 与 `order.read@**` 在旧模型里同为"无害"，在新模型里后者可触及 SECRET
级命名空间，本身即有害。旧结论是这个粒度错误的产物——它不是在论证下失效，而是在定义下失效。

我们把这条记录保留在结果文件与汇总中而非静默覆盖，因为**它本身就是本项目最想说明的问题**：
危害分类是承重的，任何只报单一分类的结果都不应被采信。

#### 6.11.2 修正后仍然成立的结论

1. **五级的敏感 surplus 恒为 0**，且在 `strict`/`lenient` 下**任何一级的危害都为 0**——
   因为协调者根授权本身不含跨界能力。粗化只能在根授权之内造成损害，
   **真正的安全参数是根授权本身**，一个静态可审计的产物。
2. **五级的任务成功率都是 13/13。** 可用性对过近似完全不敏感，不能当指标。
3. **〔粗化是否有害〕不是与分类无关的命题**（E14）：`any_harm_at_all` 在变体间不稳定。

### 6.12 粒度选择：裸动词集合 vs 资源模式化（E12）

| 声明方式 | 任务成功 | surplus 授权数 | 平均可达半径 | 可达最高敏感级 | 危害(moderate) |
|---|---|---|---|---|---|
| 资源模式化（`order.read@orders/*`） | 13/13 | 1 | 4.0 | INTERNAL | 0 |
| 裸动词集合（原实现，`order.read`） | 13/13 | 8 | 2.75 | SECRET | 8 |

两者任务成功率相同、都覆盖任务意图，差别只在 surplus。把授权从"动词"细化到"动词 × 资源模式"
把 surplus 从 8 降到 1、可达最高敏感级从 SECRET 压回 INTERNAL、危害从 8 降到 0，
**且不需要任何语言理解**——资源标识符可从环境核对。

这是本次危害模型修正后**反而被加强**的结论：在旧粒度下裸动词集合只记 1 条有害，
新粒度下记 8 条。粒度选择的价值比原先估计的更大。

### 6.13 逐跳独立 surplus（E13，修正 E2 的设计缺陷）

E2 的 α 构造使用嵌套前缀，surplus 沿链系统性相关，导致半径随 α 饱和。E13 改为逐跳独立采样，
危害按 `moderate` 变体：

| 危害类别 | 指标 | k=1 | k=2 | k=3 | k=4 |
|---|---|---|---|---|---|
| family（同能力、更宽资源模式） | 平均可达半径 | 1.6 | 2.231 | 2.357 | 2.415 |
| family | 危害(moderate)/试验 | 1.6 | 3.4 | 4.567 | 5.333 |
| cross（换成另一种能力） | 平均可达半径 | 1.233 | 1.497 | 1.659 | 2.129 |
| cross | 危害(moderate)/试验 | 1.233 | 2.6 | 4.133 | 5.833 |

**修正记录**：前一版报告「cross 有害条目多 2–6 倍」。改按（能力 × 资源）判定后该差异消失
（k=4 时 5.333 vs 5.833），仅剩可达半径的差异（2.415 vs 2.129）。旧差异来自同一个粒度错误：
family 的 `order.read@**` 在旧模型里无害，在新模型里触及 SECRET 因而有害。
全部试验（10 组 × 30 次）任务成功率均为 100%，即这条差异不体现在可用性上。

### 6.14 危害定义的稳健性扫描（E14）

| 变体 | 含义 | (级别, surplus, 危害) 序列 | 序反例对 | 条数能代理危害 | L3−L2 | 存在任何危害 |
|---|---|---|---|---|---|---|
| strict | 只算跨界效果 | L0(0,0) → L1(1,0) → L2(8,0) → L3(7,0) → L4(48,0) | 0 | 是 | 0 | **否** |
| moderate | 另含写类与个人数据读 | L0(0,0) → L1(1,0) → L2(8,8) → L3(7,6) → L4(48,48) | 0 | 是 | −2 | 是 |
| lenient | 只算外传/执行 | L0(0,0) → L1(1,0) → L2(8,0) → L3(7,0) → L4(48,0) | 0 | 是 | 0 | **否** |

跨变体稳定性：`size_predicts_harm` 稳定（三变体均为"是"），
`any_harm_at_all` **不稳定**（strict/lenient 恒为否，moderate 为是）。

三条读法：

1. **〔粗化是否有害〕不是与分类无关的命题。** 在 `strict` 与 `lenient` 下，本场景中
   所有级别的粗化危害都是 0——因为协调者根授权不含跨界能力。任何一个只报单一分类的结果都不应被采信。
2. **"surplus 条数能代理危害"在本场景反而成立**（我的初版结论说它不成立）。
   这是一个 5 点、单场景的观察，不足以推广；但足以说明初版结论是分类错误的产物。
3. **危害模型的输入若换成另一套工具清单或数据分级，本表会整体改变。**
   因此我们把 E14 的定位写成"暴露依赖性"，而不是"证明稳健"。

### 6.15 根授权粒度（E15）

把协调者根授权当自变量扫五档：

| 根授权档位 | 规模 | 含敏感能力 | strict 上限 | moderate 上限 | lenient 上限 | 敏感 surplus 上限 |
|---|---|---|---|---|---|---|
| R0 仅任务必需 | 4 | 0 | **0** | 16 | **0** | 0 |
| R1 +相邻动词 | 7 | 0 | **0** | 28 | **0** | 0 |
| R2 +运维读写 | 9 | 0 | **0** | 36 | **0** | 0 |
| R3 +导出与凭据读 | 11 | 2 | 4 | 44 | 4 | 8 |
| R4 全部能力 | 18 | 6 | 20 | 72 | 16 | 24 |

**根授权不含跨界能力时，strict/lenient 危害在五档 × 五个粗化级别下恒为 0**；
一旦纳入 `db.export` 立即跳到非零。这把 §6.11.2 那条唯一幸存的结论
（安全参数是根授权而非推导质量）从单一根授权扩到五档。

但 `moderate` 上限**不随根授权收窄而归零**：R0 只有 4 项能力，moderate 危害仍有 16——
因为读能力在 `@**` 上触及 SECRET 命名空间。因此更准确的表述是：
**危害上限 = 根授权的效果类别跨度 × 资源模式的宽度**，两个因子都要管。

### 6.16 危害模型输入的敏感性分析（E16）

扰动有争议能力的效果读法（低/高）与缺省数据分级（PUBLIC/INTERNAL/PERSONAL），共 6 份备选清单：

| 变体 | 危害上限区间 | 条数能代理危害 | 存在危害 | L3 比 L2 危险 |
|---|---|---|---|---|
| strict | [0, 16] | 6/6 | 3/6 | 0/6 |
| moderate | [48, 48] | 6/6 | 6/6 | 0/6 |
| lenient | [0, 8] | 6/6 | 3/6 | 0/6 |

上一轮的两条修正结论在**全部扰动下都成立**：`size_predicts_harm` 恒为 6/6，
`L3>L2` 恒为 0/6。而「是否存在危害」不稳定——strict/lenient 下只有一半清单为真。
这正是把"声明依赖"变成可测区间之后的样子。

### 6.17 随机拓扑性质测试（E17）

定理级断言此前只在一条固定链 A→B→C→D→E 上验证过，**代码量与定理声明的比例是不匹配的**。
现扩到 6 个固定形状（链 5/10 跳、扇出、菱形汇聚、环 3/5）+ 120 个随机委托图：
1904 个令牌、5160 条收据、2899 次副作用，**违反 0 项**。

逐图断言 P1、I1、I2、I3、I5 与「越权派生必须被拒」。同时强制检查**非平凡性**：
ALLOW 2899、DENY 2261、越权派生尝试 391、环形令牌 93。
任一项为 0 即判为测试退化并返回非零码——否则一个"全部拒绝"的实现也能通过上述断言。

### 6.18 传播半径的区间（E18）

此前的 `propagate()` 假设下游**总是**顺从转发，因此 E2/E13 报出的半径是**上界**而非期望值。
把每跳顺从建模为独立伯努利、并用新建系统逐次真实执行得到分布：

| 顺从概率 | 平均半径 | 走完全链比例 | 确定性上界 | 解析值 E[r]=Σpⁱ |
|---|---|---|---|---|
| 1.00 | 4.0 | 1.00 | 4 | 4.000 |
| 0.75 | 2.15 | 0.33 | 4 | 2.051 |
| 0.50 | 1.065 | 0.06 | 4 | 0.938 |
| 0.25 | 0.35 | 0.005 | 4 | 0.332 |

经验分布与解析预测的最大偏差 0.127（200 次试验），两者互证。
**结论：本文所有传播半径数字应读作上界。**

### 6.19 分区下的撤销窗口（E20）

| 情形 | 撤销后首次被拒 |
|---|---|
| 正常联网 | 10 tick（= 拉取周期） |
| 网络分区 | **101 tick（= TTL + 1）** |

P3（撤销延迟 ≤ 拉取周期）**以"能拉到"为前提**。分区打掉这个前提后，安全上界回落到 TTL。
这把 §6.3 的代价从"多个周期"重新定位为"**分区时长决定 TTL 的上限**"——一个部署参数，
而不是一个可以独立调优的常数。

### 6.20 gossip 协议本身（E19）

此前 `detect_split_view` 只是被实验直接调用的纯函数，协议本身没有实现。实现后（10 主体、
1 个分叉主体、每轮每位参与者交换 1 次）：

| 参与率 | 检出率 | 中位轮次 | 平均消息数 |
|---|---|---|---|
| 1.0 | 1.000 | 1 | 1.0 |
| 0.5 | 1.000 | 1 | 4.3 |
| 0.3 | 0.990 | 1 | 5.8 |
| 0.2 | 0.925 | 2 | 5.8 |
| 0.1 | 0.625 | 4 | 4.2 |

**全员参与时一次比较即检出，平均只要 1.0 条消息。** 瓶颈不是 gossip 的机制成本，
而是**没人默认在跑它**——这是可部署性问题，不是密码学问题。这个结论比"我们支持 split-view 检测"
有用得多，因为它指明了真正的拦路石。

### 6.21 复合动作与串通（E21）

`ActionRequest.required` 要求一个动作的多项能力**在同一令牌内同时成立**（原子判定）：

- 单能力请求：ALLOW
- 复合请求（同令牌内还需 `inventory.update`）：**DENY（SCOPE_VIOLATION）**
- A 合法地把两项能力一并授出后，同一复合请求：ALLOW
- 串通者 {B, C, D} 的根授权并集**确实覆盖**该组合要求：True —— 但仍拼不出来

这修正了 §6.9 的保守性（单能力动作模型下串通天然无效）。同时必须说清它买不到什么：
**分时串通不受限**（X 读完把数据交给 Y 外传）。复合动作封的是"一次操作需要多项能力"，
不是"多个主体合作"。这是残余风险，不是可以靠机制消除的。

### 6.22 漂移检测阈值的 ROC 标定（E22）

§6.6 的阈值 3.5 是拍出来的。扫描后：

| 阈值 | recall | 硬正常 FPR | 告警数 |
|---|---|---|---|
| 3.5（原默认） | 1.0 | **0.717** | 83 |
| 8.5 | 1.0 | 0.100 | 46 |
| 12.5（工作点） | 1.0 | **0.000** | 40 |
| 14.0 | 0.575 | 0.000 | 23 |

**原来的 3.5 偏低约 3.6 倍**：提到 12.5 可在 recall 保持 1.0 的把硬正常 FPR 从 0.717 压到 0.0。
这仍是确定性统计代理的 ROC，不代表 LLM 检测器；但"阈值不该拍"这一点是通用的。

现换成 4 条基线 × 8 种可复现变换 = 32 条语料：

### 6.24 实测延迟（E24，取代 §6.4 的模型化折算）

§6.4 的"中央 RTT"是拍的 1.5ms。实测（本机 IPv4，300 次回环 + 8 次公网连接）：

| 基准 | 中位往返 |
|---|---|
| 回环裸 TCP | 0.24 ms |
| 回环 HTTP（`TCP_NODELAY`） | 0.41 ms |
| 回环 HTTP（默认，Nagle 生效） | **44.02 ms** |
| 公网 `api.deepseek.com` TCP 连接 | 7.5 ms |
| 公网 `pypi.org` TCP 连接 | 79.4 ms |

每请求端到端延迟（实测本机 CPU + 实测 RTT）：

| 模式 | 本机(ms) | 额外往返/请求 | 回环(关Nagle) | 公网 api | 公网 pypi |
|---|---|---|---|---|---|
| P | 0.374 | **0.1** | 0.41 | 1.13 | 8.32 |
| B1 | 0.345 | 1.0 | 0.75 | 7.87 | 79.76 |
| B2 | 0.163 | 0.0 | 0.16 | 0.16 | 0.16 |
| B0 | 0.155 | 0.0 | 0.16 | 0.16 | 0.16 |

**两处更正。**

其一，**§6.4 把 P 的每请求额外往返记为 0 是错的**。P 不需要每次请求回中心，但仍需周期性
拉取撤销状态，每次拉取是一次真实往返。摊到每请求上是 `1/(pull_interval × 每 tick 请求数)`，
在上表参数下为 0.1。请求率越高该项越小，但在低请求率下不可忽略。这个数字此前被写成 0，
是把"不参与每次判定"错误地等同于"不产生任何协调流量"。

其二，**Nagle 伪影**。回环 HTTP 用默认服务端（分次 write、未设 `TCP_NODELAY`）时，
中位往返 44.02ms，关闭后 0.41ms——**伪影 43.61ms，是真实回环 RTT 的约 180 倍**。
这意味着：若 PEP↔PDP 通道照默认 HTTP 服务端实现，B1 的延迟会被这个协议栈伪影完全主导，
而它与"中心化本身的代价"毫无关系。**任何在回环上做的延迟对比都必须先排除它**，
否则结论无法迁移到真实部署。

### 6.25 AgentDojo 公开注入语料（E25）

§6.23 的绕过率基于自造语料。为消除自造偏差，按 AgentDojo 自身的构造方式
（`attack_template.format(goal=goal)`）组合出其官方语料：

- 来源：`agentdojo 0.1.35`（MIT，ETH Zurich SPY Lab）
- 54 个官方注入目标 × 5 个官方攻击模板 = **230 条载荷**（丢弃 40 条含无法静态解析的占位符者）
- 构建期联网抽取一次，落到 `data/agentdojo_corpus.json`；**实验期只读本地文件，不联网**

| 模式 | 载荷 | 放行 | 绕过率 |
|---|---|---|---|
| P | 230 | 0 | 0.000 |
| B1 | 230 | 0 | 0.000 |
| B2 | 230 | 225 | **0.978** |
| B0 | 230 | 230 | 1.000 |

B2 逐 suite：banking 70/75、slack 25/25、travel 40/40、workspace 90/90。

#### 6.25.1 这次替换推翻了我们自己上一批的数字

自造语料上 B2 绕过率 0.656，真实公开语料上是 0.978。差异的来源是可诊断的：
我按"看起来像攻击"的方式造样本，样本里塞了 `export`/`credential`/`admin` 这类关键词，
而**真实攻击载荷是自然语言目标，根本不含这些词**。因此：

> **用自造语料评估提示层护栏会系统性偏乐观。** 这不是语料规模问题，是造样本的立场问题——
> 防御方造的"攻击样本"会不自觉地向自己认得的特征靠拢。

#### 6.25.2 这个实验不证明什么

这些载荷是**文本**，而本方案的强制不在文本路径上。P 全部拒绝，只是重复 §6.8 的结论
（判定不读 `req.text`），**不构成抗注入证据**。任何把"P 的绕过率为 0"读作"本方案抗注入"
的推论都是错的。

#### 6.25.3 有信息量的两个量

其一，**提示层护栏在真实公开语料上的拦截率仅 2.2%**。这是对 §6.7 的实质更新。

其二，**可表达性**：230 个官方目标中，200 个（86.9%）可按关键词规则映射到我们的能力集合，
其中落在被委托令牌范围内的 **0 个**——即按该规则，全部攻击的工具调用实现都在委托范围之外。
但必须附加两条限定：(a) 映射规则由本仓库给出，只是可表达性的上界估计，不是真值；
(b) 它掩盖了真正的残余风险——"读出护照号再外传"这类目标，**读是范围内的**，
只有外传是范围外的，属于 confinement 问题，scope 强制只能挡住后半段。

### 6.26 真实工具集基底（E26）

E11–E16 的全部结论都建立在自造的能力宇宙上。这一节把基底换成 AgentDojo 的真实工具集：

- capability = 真实工具函数名（69 个 suite 工具）
- 真实任务 = 用户任务 `ground_truth()` 里的 `FunctionCall(function=..., args=...)`
- **危害集合 = 注入任务 `ground_truth()` 调用的工具**（21 个）——由基准自身定义，非本文手写
- effect 类别由函数体静态分析得出；该规则与独立的 docstring 动词交叉验证 **69/69 一致**
- 相邻动词 = 首个非环境参数名相同的工具（"同一个对象、换个动词"），机械得出

先做复现校验：把广义化实现跑在玩具基底上，得到 surplus 序列 `[0,1,8,7,48]`，
与 E11 完全一致——**复现不通过则新基底的数字不予采信**。

各粗化级别下落在基准危害集合内的 surplus 授权数：

| 基底 | L0 | L1 族放宽 | L2 丢对象 | L3 动词过泛 | L4 无推导 | 最危险级 | 序反例对 |
|---|---|---|---|---|---|---|---|
| 玩具（E11 基线） | 0 | 0 | **8** | 6 | 48 | L4 | 0 |
| agentdojo/banking | 0 | 4 | 4 | **0** | 14 | L4 | 0 |
| agentdojo/slack | 0 | 1 | 4 | **12** | 31 | L4 | 0 |
| agentdojo/travel | 0 | 3 | 4 | 3 | 21 | L4 | 1 |
| agentdojo/workspace | 0 | 0 | 0 | 0 | 20 | L4 | 0 |

**结论一（稳健）**：最危险级别在全部基底上都是 L4「无推导」。这条从自造宇宙迁移到了真实工具集。

**结论二（不稳健，且各 suite 相互矛盾）**：L1/L2/L3 之间的排序完全无法迁移。
玩具是 L2>L3>L1（L1 无害）；banking 是 L1=L2>L3，**L3 最轻**；
slack 是 **L3>L2>L1**，与 banking 相反；travel 是 L2>L1=L3；
workspace 三者**全为 0**，只有 L4 有代价。
**E11 里"哪种推导失误最危险"的排序是玩具宇宙的产物，不能外推。**

**结论三**：「surplus 条数能代理危害」在 3/4 真实 suite 上成立，travel 上不成立
（L2 的 11 条 surplus 有 4 条恶意，L3 的 44 条只有 3 条）。E16 的结论仍成立，
但**只在统计意义上**。

#### 6.26.1 过程中修掉的两个框架缺陷

其一，无字符串参数的工具在需求轨迹里被记为资源 `""`（→ 模式 `**`），
运行期却用两段占位符，导致反推出的 M 无法复现任务。
其二，「对象族放宽」对已经是 `**` 的模式做"最后一段换成 `*`"，把它**收窄**了，
反而让任务失败——粗化永远不该收窄。

两者都**不是**架构发现。值得注意的是：**玩具复现校验一个都没抓到**，
是每-suite 的任务成功率列抓到的。这说明——

> **"先在已知基底上复现"是必要条件，不是充分条件。**
> 复现校验只能证明"没改坏已知路径"，抓不到"新路径上的新错误"。
> 还必须输出逐项合理性列（这里就是任务成功率）作为哨兵。

## 7. 局限

1. **漂移检测器是确定性统计代理，不是 LLM 检测器**，其 FPR/Recall 不能外推到 LLM 实现。
2. **自然语言→范围（语义衰减）仍未实现**：E11–E13 用"任务轨迹反推 + 人工粗化阶梯"
   替代了 LLM 推导，因此测出的是**推导质量的代价函数**，不是真实 LLM 推导的质量。
   把粗化阶梯的四个级别换成四种真实 LLM 推导器，是下一步工作，也是本工作最大的缺口。
3. **传播模型是最坏情况**：假设下游主体顺从地转发任务。真实系统中下游可能拒绝。
4. **单能力动作模型**：不支持需要多能力联合的动作，因此 E9 的串通测量偏保守。
5. **延迟数据**：墙钟为本机 CPU 时间（实测）；网络 RTT 已在 §6.24 改为实测，但只覆盖 TCP 连接建立与回环 HTTP，未做多地域、并发与拥塞条件下的测量。
6. **规模**：5 主体链、数百请求量级，未做大规模拓扑与真实网络实验。
7. **权威与 PEP 是 TCB**：进入 TCB 的攻击不在防护范围内。
8. **危害模型的两个输入仍是声明的**：工具清单的效果类别与数据目录的命名空间分级由本仓库声明，
   真实部署中应来自系统。本工作只保证了**聚合规则**被显式扫描，未保证输入本身无争议。
   已知残留缺陷：`reachable_sensitivity` 用各命名空间的代表资源做匹配，对语法受限的模式语言是精确的，
   换成更复杂的模式语言后需要重做。
9. **E11 的"最小必要范围"是最具体公共前缀泛化，不是理论最优最小集**（后者是 NP-hard 的集合覆盖）。
   因此 `S \ M` 是过近似的一个**下界**估计。

## 8. 开放问题

E11–E14 把"范围表达能力"从开放问题推进了一半：现在有了可计算的最小必要范围 M、
可解释的四级粗化阶梯，以及**对分类选择做显式扫描**的危害度量。
最重要的一条经验是方法论层面的：危害定义是承重的，因此它必须被当作实验变量而非前提。
剩下的一半是**真实推导器**：

1. 把四个粗化级别换成四种真实的 NL→范围推导器（正则抽取 / schema 约束的 LLM 推导 /
   多路自洽投票），测量它们在三个维度上的位置：任务成功率、surplus 危害、人工仲裁量。
2. **用多路推导的分歧度预测过近似**：对同一子目标做 k 路独立推导，用 Jaccard 离散度衡量分歧。
   分歧高说明该子目标的约束本身不可判定，此时不应走"猜准"路线，而应路由到窄起步+按需加宽或人工。
   （本工作未接入 LLM 推导器：环境中无可用 LLM 凭证，因此这一路未验证。注意这不是连通性问题——本机网络可用，缺的是凭证与预算决策。）
3. 根授权设计：E11 表明粗化的危害被根授权封顶，因此安全投入的边际收益可能在**根授权**而非推导质量上。
   这需要一组根授权粒度实验。

**"窄起步 + 按需加宽"为何未被采纳**：它的证据来自被怀疑方本身（是 Agent 在申请加宽），
校准价值低于反事实收缩；但它作为**运行时**机制仍有独立价值（把一次性猜测换成带审计痕迹的单调收敛），
与本工作正交，应分开评估。

## 9. 与已有工作的关系

衰减式凭证（Macaroon / Biscuit / ZCAP-LD）是本工作 §3.2 的直接基础，**本工作不声称发明它**。
局部命名与本地信任视图的前身是 SPKI/SDSI 与 web-of-trust；有界撤销延迟与等价分歧检测
来自 OAuth 短令牌与 Certificate Transparency；监督者-批评者模式在多 Agent 文献中已有大量工作，
本工作刻意放弃了"B 监督 A"的表述（见 §10）。

本工作的差异在于：把委托范围落到可离线验证的凭证结构，并在 LLM Agent 的委托拓扑上
**测量两件事**——横向传播能力面的收缩幅度，以及语义衰减的过近似代价。
这是一个**评估型**工作，不是一个新机制。

## 10. 设计取舍记录

- 放弃"委托产生监督"的表述：监督是职责声明，无法强制；衰减与归因是机制，可证明。
- 放弃"局部身份视图"：授权只取决于范围，把角色作为判定输入会重新引入"自我声明的身份影响信任状态"。
- 放弃 Identity/Credential/Key 三版本制：实际需求只有单调性（防回滚）与有界陈旧（撤销延迟）。
- 检测器移出接收端：接收端与被检测者共享输入链路，检测器本身可被注入。
- 处置顺序改为 令牌 > 边 > 主体 > 人工：撤销令牌半径最小、无需人工。
