# 形式化规格 v1

对应架构文档 `agent-security-v2.md`。本文件定义对象、代数、协议与不变式；实现见 `src/`，实测见 `results/`。

---

## 1. 记号

- `S = {s_1..s_n}`：主体（Agent）。每个主体 = 一个不可信规划进程 + 一个可信 PEP。
- `C`：能力标识符全集（capability universe），如 `order.read`、`db.export`。
- `scope ⊆ C`：授权集合。**实现期修正**：一条授权不是裸能力标识符，而是
  `capability@resource_pattern`（见 §2.8）。裸标识符等价于"任意资源"，
  因此 v1 的裸动词集合是本模型的最粗特例。集合包含关系相应升级为**模式语言包含**。

## 2. 对象

### 2.1 Subject
```
Subject { subject_id, role, pubkey, key_epoch, }
```
`role` 仅用于日志与人读，**不参与任何授权判定**。原因：v1 的身份一致性检测建立在"角色可变且需验证"之上，而授权实际只取决于 scope；保留 role 作为判定输入会重新引入"自我声明的身份影响信任状态"这一漏洞。角色变更的语义影响通过重新签发 root grant 的 scope 体现。

### 2.2 RootGrant（权威签发）
```
RootGrant { subject_id, scope, key_epoch, cred_epoch, issued_at, not_after, sig }
（`sig` 为权威签名）
```
- `cred_epoch` 单调递增；验证方缓存 `max_seen_epoch[subject_id]`。
- `not_after = issued_at + ttl`。

### 2.3 Token（衰减式委托令牌）
```
Token {
  token_id, root_subject_id,
  holder_id,
  scope,               # 当前（已衰减）范围
  task_id, parent_task_id,
  not_after,
  depth, redelegatable,
  chain: [ Link ]
}
Link { parent_token_id, token_id, attenuator_id, attenuator_key_epoch,
       holder_id, scope, task_id, parent_task_id, not_after, depth,
       redelegatable, sig }
```
派生规则（`attenuate`）——**规则 1–5 的列举顺序即为检查顺序**（与 §2.3 verify 同理；
第二轮差分测试发现此前未声明顺序，两套独立实现各取一种，在“父令牌已封条且子范围越界”时
分别报 `SCOPE_VIOLATION` 与 `NOT_REDELEGATABLE`）：
1. 派生者必须持有父令牌，且 `parent.holder_id == 派生者`。
2. `scope_child ⊆ scope_parent`，否则拒绝派生。
3. `not_after_child = min(now + ttl, not_after_parent)`——**截断而非拒绝**。（早期规格写作〔否则拒绝〕，与实现冲突；独立复现指出两种读法都通而规格未定，此处按实现钉死。）
4. `depth_child = depth_parent + 1`。
5. `parent.redelegatable` 为假时拒绝派生（`NOT_REDELEGATABLE`）。见 §2.7。

验证规则（`verify`，纯离线）：
1. 根的 `RootGrant.sig_A` 用 `K_A` 验通，且 `grant.subject_id == token.root_subject_id`。
2. 对每个 Link：用 `attenuator` 的公钥验签；`new_scope ⊆ 上一级 scope`；`not_after` 单调不增。
3. `Link.parent_token_id` 与链上前一项一致，且每一项的 `token_id` 可由**前一项的字段**重算验证：`token_id = H(parent_token_id, holder_id, scope, task_id, not_after, depth, redelegatable)`。独立复现指出：只有当 `Link` 携带上述全部字段时才可离线重算——规格早先的 `Link` 定义缺少这些字段，使该规则不可执行。字段定义已按 §2.3 修正。
4. 当前时间 ≤ `not_after`。
5. `token_id ∉ revoked`；`holder_id ∉ revoked_subject_ids`。
   规则 5 的「主体」指**持有者**（`token.holder_id`），**不是**链根主体——
   即 `revoke_subject` 只使该主体**作为持有者**的令牌失效。
   （第三轮全新读者指出规格未定义此处，两种读法会给出不同的原因码。）
6. 所有涉及的 `key_epoch >` 验证方记录的 `revoked_key_epoch` 上限（严格大于；等于即为已作废）。
   **「所有涉及」= 链根授权的 `key_epoch` ∪ 各级 `Link.attenuator_key_epoch`；不含持有者自身**
   （第三轮全新读者实测确认）。
   该失败报 **`TOKEN_REVOKED`**（全新读者按规格无从推断、选了 `TOKEN_INVALID`，此处钉死）。
7. 末链的 `redelegatable` 与 token 字段一致。

**链根的表示（第二轮差分测试后钉死）**：离线验证需要一个可确定的“链根标识”：
有链时为 `chain[0].parent_token_id`，无链时为 `token.token_id` 本身。
验证方以该标识在权威的授权历史中解析出令牌链**实际根植**的那份授权。
（此前只写“按链根解析”而未定义链根，离线验证的输入无法确定。）

**检查顺序（差分测试后钉死）**：规则 4–6 的**触发优先级为 撤销 → 过期 → 密钥作废**。
此处“撤销”**仅指规则 5**（令牌/主体被 `revoke_token`/`revoke_subject`），
密钥作废（规则 6）是单列的第三级——参考实现曾把密钥检查放到过期之前，
在“未撤销、已过期、且密钥作废”时报 `TOKEN_REVOKED`，与本句不符（第二轮差分测试判定为它的 bug，已修）。
即令牌同时已撤销且已过期时，报 `TOKEN_REVOKED`。理由：撤销是安全相关事实，
过期只是时间事实；把撤销报在前面便于审计定位。早期规格只列出规则而未说明顺序，
两套独立实现各选一种，产生分歧。

**关键推论（P1 的机制来源）**：派生者无法构造 `scope ⊄ scope(自己)` 的合法子令牌，因为每一级都需上一级的私钥签名且范围单调收缩。**因此被完全注入的主体在密码学上无法授出自己不具备的权限。**

### 2.3.1 签发者语义（实现期修正）

令牌有三个角色，必须区分：

- `holder`：**被授权去执行**的一方（令牌的接收者）。
- `issuer = token_issuer(token)`：链上最后一级衰减者；无链时等于 `root_subject_id`。
- 请求方：`ActionRequest.from_id`。

接收方的判定要求 **`token_issuer(token) == req.from_id`**，即"只有把这份范围授予我的人，才能以这份范围来驱使我的 PEP"。持有者本人不能自己拿这份令牌去请求别人。这条在 v1 中缺失，是首轮实现中暴露的语义空洞。

### 2.4 ActionRequest
```
ActionRequest { request_id, from_id, to_id, task_id, token_id,
                capability, resource, params_hash, nonce, ts,
                text, required, sig }
（`text` 为规划进程的自然语言负载，判定禁止读取；`required` 为复合动作的其余能力；
  `sig` 为发送方 PEP 签名）
```
由发送方 **PEP** 签名。签名提供**归因**，不提供授权。规划进程可以提议任意 capability，PEP 会照签——因为拒绝越权的责任在接收方（这正是"强制点在接收端"）。

发送方 PEP 可选做快速拒绝（fail-fast），但不构成安全边界，规格中标注为优化。

### 2.5 Receipt
```
Receipt { receipt_id, from_id, to_id, request_id, token_id, task_id,
          capability, resource, decision, reason_code, ts, drift_score, sig }
（`decision ∈ {ALLOW, DENY}`；`sig` 为接收方 PEP 签名；
  `drift_score` 由证据平面回填、不参与签名）
```
- 由**接收方 PEP** 签名。
- **权威副本只进证据平面**，不回传发送方。实现中 `PEP.handle` 会把同一个对象返回给调用方，
  因此**返回的那份不具权威性**，任何仲裁都必须以证据平面中的签收副本为准。
  （规格与实现的这处差异由外部审读发现，此处按实现修正表述。）
- 攻击者可控制请求内容，但无法伪造接收方签名 ⇒ **收据是发送方实际行为的地面真值**，且为结构化字段。

`reason_code ∈ {OK, SCOPE_VIOLATION, TOKEN_EXPIRED, TOKEN_REVOKED, TOKEN_INVALID, TASK_MISMATCH, REPLAY, NOT_REDELEGATABLE, REQUEST_UNSIGNED, STALE_CREDENTIAL, PDP_UNAVAILABLE, GUARD_BLOCK, RECEIPT_INVALID, LOCAL_FAILFAST}`

（早期清单含 `UNKNOWN_TASK`，但实现从不产生它——由下面的机械检查发现，已删除。规格声明的每个 reason_code 都必须由实现可达。）

其中 `STALE_CREDENTIAL`（凭证回滚）、`REQUEST_UNSIGNED`（归因失败）、`NOT_REDELEGATABLE`（转委托被禁）、`PDP_UNAVAILABLE`（仅 B1）、`GUARD_BLOCK`（仅 B2）、`LOCAL_FAILFAST`（发送端 fail-fast 优化）为实现新增。

### 2.6 RevocationEpoch（权威签发）
```
RevocationEpoch { epoch, revoked_token_ids, revoked_subject_ids,
                  revoked_key_epochs, log_head_hash, issued_at, sig }
```
`log_head_hash`：截至该 epoch 的撤销记录哈希链头。用于 split-view 检测。

### 2.7 转委托封条（实现期新增）

`Token.redelegatable`：为假时该令牌的持有者不得再向他人派生（`NOT_REDELEGATABLE`）。
默认真。理由见 §9 的 E10：没有这条封条时，被攻破主体可把自身令牌范围复制给任意多同伴，
**节点级半径无上界**；加封条后节点半径归零，能力面不变。

### 2.8 资源模式与范围包含（实现期新增）

语法刻意受限，以保证包含关系可判定且廉价（授权判定必须离线、常量时间量级完成）：

```
PATTERN := segment ( "/" segment )* [ "**" ]
segment := 字面量 | "*"
"**" 只能作为最后一段，表示"任意剩余段（含零段）"；空模式 "" 等价于 "**"
scope 条目 := "capability" | "capability@PATTERN"
```

- `matches(p, r)`：资源串 r 是否落在模式 p 的语言内。
- `subsumes(p, q)`：p 的语言 ⊆ q 的语言。**健全性要求**：`subsumes(p,q)` 为真时，
  任何匹配 p 的资源必须匹配 q。反向不要求——漏判只导致误拒，不导致越权。
- `scope_subset(child, parent)`：child 的每条授权都被 parent 中同能力的某条授权包含。
  **这才是衰减的代数学核心**——不是集合包含，是模式语言的包含。
- `scope_allows(scope, cap, res)`：请求判定。

性质测试（`experiments/selfcheck.py`，4000 组随机抽样）：
- subsumption 健全性（0 反例）；
- **衰减不放大权限**：子范围允许的请求，父范围必须也允许（0 反例）。

这两条测试在实现期抓到一个真实缺陷：`a/**` 曾被判为 `a/*/**` 的子集。
错因是**前缀更短时 `**` 允许的短路径不在后者的语言里**（`a/**` 含路径 `a`，`a/*/**` 要求至少两段）。
该缺陷会让衰减检查放行一个实际上更宽的范围，属于**健全性漏洞**，已修正。

**段不得为空（差分测试后钉死）**：资源串按 `/` **精确切分，不做任何归一化**。
含空段者（前导 `/`、尾随 `/`、连续 `//`）**不匹配任何有约束的模式**；
只有无条件模式（空串或 `**`）匹配一切，含退化资源串。

早期实现静默 `strip("/")`，把 `a/`、`//a` 与 `a` 视为同一资源——既无规格授权，
又是路径归一化类授权绕过的经典来源。`matches` 与 `subsumes` 必须共用同一套空段规则，
否则二者不自洽（而不自洽正是不健全的来源）。

### 2.9 最小必要范围 M（可计算真值）

过近似率 α 在原设计中是外部扫描参数。实现期改为**从任务轨迹反推的可计算量**：

1. 用宽松范围跑一遍任务，记录实际放行的 `(跳, 能力, 资源)` 轨迹；
2. 对每个（跳, 能力）取其资源集合的**最具体公共前缀泛化**（`least_general_pattern`）；
3. 第 i 跳的范围必须覆盖"本跳自身需求 ∪ 全部下游需求"——因为第 i 跳的令牌是第 i+1 跳令牌的父令牌；
4. `M_i` 即第 i 跳的最小必要范围。

**这不是理论最优最小集**（最小集问题是 NP-hard），是"最具体公共前缀"这一可判定的近似。
其价值在于：把"过近似"从一个人为参数变成 `S \ M` 这个**可算的差集**。

### 2.10 度量：危害必须按（能力 × 资源）判定，且聚合规则必须被显式扫描

代价度量不能是集合大小，也不能是单一分类下的"有害条数"。规则（见 `src/harm.py`）：

1. **危害的输入取环境自身的声明**：工具清单给出每个能力的效果类别（READ/WRITE/EXPORT/
   EXEC/ADMIN/DELEGATE）与可逆性；数据目录给出资源命名空间的敏感级别
   （PUBLIC/INTERNAL/PERSONAL/SECRET）。这些是**事实**，不是研究者的判断。
2. **危害按（能力 × 资源模式）判定**。按能力贴标签与授权模型自相矛盾：
   `order.read@orders/*` 与 `order.read@**` 的危害不同，后者可触及 SECRET 命名空间。
3. **聚合规则是研究者的判断，因此必须作为变体显式扫描**（`strict`/`moderate`/`lenient`），
   并报告哪些结论跨变体稳定、哪些不稳定。

实测（E11/E13/E14）的教训：初版用手写能力表得出的两条结论（L3 最危险、条数不能代理危害）
在改为正确粒度后**都被推翻**，且 `any_harm_at_all` 本身在变体间不稳定。
因此规格要求：任何只报单一危害分类的结果不得作为结论。

### 2.11 危害模型输入的扰动与根授权粒度

- **输入扰动**：`CONTESTED_EFFECTS` 列出效果类别存在多个可辩护读法的能力（其余不动），
  对其取最低/最高危害读法；缺省数据分级在 PUBLIC/INTERNAL/PERSONAL 间扫描。
  共 6 份备选清单 × 3 个聚合变体。实测：`size_predicts_harm` 与 `L3>L2` 在全部扰动下不变，
  `any_harm_at_all` 不稳定。
- **根授权粒度**：危害上限的**跨界部分**是根授权的函数而非推导质量的函数——
  根授权不含跨界能力时，`strict`/`lenient` 危害在五个档位、五个粗化级别下恒为 0。
  但 `moderate` 上限不随根授权归零：读能力在 `@**` 上触及 SECRET 命名空间。
  故危害上限由**两个因子**共同决定：根授权的效果类别跨度，与资源模式的宽度。

### 2.12 复合动作与分区的建模要求（实现期新增）

- **复合动作**：`ActionRequest.required` 为 `"cap@resource"` 序列。判定要求
  `{capability@resource} ∪ required` **全部**落在同一令牌范围内，否则整体拒绝（原子）。
  它封的是"一次操作需要多项能力"，**不封"多个主体分时合作"**——后者是残余风险。
- **网络分区**：`PEP.partitioned` 为真时停止拉取撤销状态。
  P3（撤销延迟 ≤ 拉取周期）**以"拉得到"为前提**；分区打掉该前提后，
  安全上界的正确表述是 **`pull_interval + ttl`**（实测 101 tick ≈ TTL + 1）；
  “回落到 TTL”是近似说法，正文须用前者。因此 TTL 的选择受分区时长约束，而非仅由可用性约束。

### 2.13 阈值与语料的标定要求

- 任何检测阈值**不得硬编码为拍定的常数**：`experiments/robustness.py` 的 ROC 扫描
  给出 (recall, FPR) 前沿与"在给定 FPR 上限下 recall 仍为 1"的工作点。
  实测：原默认 3.5 的硬正常 FPR = 0.717；工作点 12.5 时 recall 仍为 1.0 而 FPR = 0.0。
- 对抗文本语料**不得是少量手写样本**：须由可复现的变换规则程序化生成，
  并逐变换报告结果（实测 B2 在同形字/零宽字符/插空格/leet 上全线失守）。
- 传播半径须报告**区间**：只给"下游总是顺从"的上界会系统性高估。
  经验分布须与解析预测交叉验证。

### 2.14 延迟报告要求

- 网络 RTT **不得使用拍定的折算常数**，须实测，并注明测量时点与网络位置。
- 每请求的**额外协调往返**必须包含**撤销状态拉取的摊还值** `1/(pull_interval × 每tick请求数)`。
  把不参与每次判定等同于零协调流量是错误。
- 在回环上做延迟对比**必须先排除 Nagle/延迟 ACK 伪影**（设 `TCP_NODELAY` 并报告开关两种结果），
  否则测到的是协议栈行为而非架构差异。

### 2.15 对抗语料的来源要求

- 护栏类结论**不得只基于自造语料**：自造样本会不自觉地向"看起来像攻击"靠拢
  （塞入关键词），从而**系统性高估护栏**。实测：同一护栏在自造语料上绕过率 0.656，
  在 AgentDojo 官方语料上 0.978。
- 语料构建须**复现官方构造方式**而非抄录句子，并记录 provenance（包名、版本、许可证、
  抽取方法、丢弃项）。
- **构建期可以联网，实验期不得联网**：语料落到 `data/`，实验只读本地文件，
  缺失时标记为不可用而不是失败。
- 报告绕过率时**必须声明该实验不测什么**：在本方案中，文本载荷不经过强制路径，
  因此"拒绝全部文本载荷"不是抗注入证据。

### 2.16 外部锚定要求（含装置自证禁令）

- 凡是能用**外部真值**替换的自造输入，**不得只报自己那一版**。已识别的自造输入及其外部锚定：
  | 自造输入 | 外部锚定 | 结果 |
  |---|---|---|
  | 危害能力表 | 基准注入任务的 `ground_truth()` | 推翻两条结论（E14） |
  | 攻击语料 | AgentDojo 官方语料 | 绕过率 0.656 → 0.978（E25） |
  | 网络 RTT | 实测（冻结于 `data/measurement_rtt.json`） | 见该产物的派生比值字段 |
  | 能力宇宙 | AgentDojo 真实工具集 | 见下 |
- **能力宇宙的可迁移性**：过近似实验必须在真实工具集上重跑。实测（E26）：
  「最危险级别 = L4 无推导」可迁移；**L1/L2/L3 之间的排序不可迁移**，
  且不同 suite 之间相互矛盾（banking 上 L3 最轻，slack 上 L3 最危险）。
- **广义化实现必须先复现已知基底**（E26 用玩具基底复现 E11 的 `[0,1,8,7,48]`），
  复现不通过则新基底上的数字不得采信。
- **复现校验必要但不充分**：还须输出逐项合理性列（如每-suite 任务成功率）作为哨兵。
  E26 的两个框架缺陷中，玩具复现校验只抓到零个，逐项列抓到两个。
- **粗化必须是单调的**：粗化只允许放宽，任何使任务成功率下降的"粗化"都是缺陷。


**装置自证禁令**（外部审读后并入）。外部审读（无本会话上下文的独立读者）发现：
本规格的若干〔结论〕是**实验装置的构造决定的**，而不是被测量的性质。禁止以下四类构造。
并入理由：与外部锚定是同一件事的不同面——**把信任锚从作者身上移出去**。

1. **基线与被测器件共用代码路径。** 中心 PDP 基线曾直接调用本方案的判定函数，
   使"两者安全等价"成为同义反复。基线的判定逻辑必须**独立实现**，
   或明确标注该对照只用于成本比较、不用于安全性论证。
2. **被测集合被构造钳制。** 粗化的每一级都曾被过滤到 ⊆ 根授权内，
   于是"根授权不含跨界能力 ⇒ 各级危害恒 0"成为定义蕴含。若结论要成立，
   必须存在一条**能超出该约束**的路径（如凭证伪造、降级失败后的越权授予），否则只能作为实现说明。
3. **包络级必胜。** 若某一级是其余各级的超集，而指标对集合单调，
   则"该级最严重"必然成立、无信息量。此类比较必须改测**绝对分布**，或剔除包络级。
4. **断言调用被断言的同一函数。** 性质测试不得用判定路径自身的函数来判定"是否越权"，
   须独立重算；非平凡性检查也不得只排除"全部拒绝"这一种退化。

同时：任何**单侧最优**的表述（"该级最危险""该基线失效"）必须给出对照面
（其余各级的绝对值、该基线在别处的表现），否则视为选择性陈述。

### 2.17 性质测试的覆盖要求

定理级断言（P1/P5、I1–I5、越权派生被拒）**不得只在单一拓扑上验证**。
`experiments/topology_tests.py` 在固定形状（链 5/10 跳、扇出、菱形汇聚、环 3/5）
与随机委托图上重复验证，并强制检查**非平凡性**：必须出现 ALLOW、必须出现 DENY、
必须发起过越权派生尝试、必须构造出环形委托。任一项为 0 即判为测试退化并返回非零退出码——
否则"全部拒绝"的实现也能通过断言。
- `A`：权威（Authority），持 `K_A`（Ed25519）。**TCB**。
- `E`：证据平面，只读收据流。**TCB**。
- 主体 s 的 PEP 持 `K_s`。规划进程不持任何密钥。**PEP ∈ TCB**。

信任假设：攻击者可完全控制规划进程；不可读写 PEP、A、E 的密钥与状态。

## 3. 协议

### 3.1 委托

**令牌副本**：委托方**不保留**所授令牌的可用副本；令牌只存于**持有者**的 PEP。
（此前未写明，第二轮差分测试发现两套实现分别只存接收方 / 双方都存。）
```
A_pep: t = attenuate(parent_token, holder=B, scope=S_child, task=T, ttl=τ)
A_pep → B_pep: Delegate(t)          # 携带 request_id 以便收据归因
B_pep: verify(t, root_grant_A, now, revoked) 失败则拒；成功则存入本地 token store
```
不发生对权威的调用。`scope(child) ⊆ scope(A)` 由 §2.3 保证。

### 3.2 请求—判定（接收端强制算法）

**时效窗口是双向的（差分测试后钉死）**：`max_request_age` 的默认值为 **50 tick**。
可接受区间为 `[now - max_request_age, now + clock_skew]`，其中 **`clock_skew` 为允许的时钟偏移**、
默认 0、可按接收方配置。（`clock_skew` 此前未写进规格，是全新读者发现的缺口——
它使 `ts` 为未来但不超过 skew 的请求被接受，与"拒绝远期时间戳"的意图需并列陈述。）
判定为 `-clock_skew ≤ now - req.ts ≤ max_request_age`——**未来时间戳超出 `clock_skew` 即拒绝**。
（此处曾写作「`0 ≤ now - req.ts`——未来时间戳同样拒绝」，与上一句引入 `clock_skew` 后的区间
**自相矛盾**：前者会拒绝 `ts` 领先 `[1, clock_skew]` 的请求，后者放行。第三轮全新读者发现；
原文那句只在 `clock_skew = 0` 时成立。）
早期规格只写了上界 `now - req.ts ≤ max_request_age`，按字面读法可让攻击者把 `ts`
设到远期，使该请求在任意久之后仍"未过期"，**等于取消重放窗口**。
（参考实现本来就做了双向检查，是规格漏写；独立实现按字面读法因而可被利用。）

**`RootGrant` 的来源**：接收方自行持有其信任的根授权副本（凭据由权威签发后分发，见 §3.1 的公开目录）。判定接受该副本作为输入，不通过网络获取。独立复现指出规格未定义此处，已补。
```
on_request(req) -> decision:
  1. 归因检查:  req.sig 由 from_id 的 PEP 公钥验通      else DENY REQUEST_UNSIGNED
  1b.重放检查:  (from_id, req.nonce) 未出现过           else DENY REPLAY
  1c.时窗检查:  -clock_skew ≤ now - req.ts ≤ max_request_age   else DENY REPLAY
  2. 令牌查找:  t = store[req.token_id]                 else DENY TOKEN_INVALID
  3. 签发者绑定: token_issuer(t) == req.from_id         else DENY TOKEN_INVALID
  4. 回滚防护:  grant.cred_epoch ≥ max_seen_cred[root_subject_id]   else DENY STALE_CREDENTIAL
              （`max_seen_cred` **按主体**记录，见 §2.2）
  5. 离线验证:  verify_token(t)                         else DENY TOKEN_INVALID/EXPIRED/REVOKED
  6. 任务绑定:  t.task_id == req.task_id                else DENY TASK_MISMATCH
  7. 范围检查:  req.capability ∈ t.scope                else DENY SCOPE_VIOLATION
  8. 执行副作用（世界模型）
  9. sign receipt, 送 E；返回 decision
```
步骤 1–7 全部为本地判定，**不调用任何中心、不做 LLM 推理、不读取 `req.text`**。
第 8 步之外无副作用。`req.text` 仅在 B2 基线中被读取（见 §9）。

### 3.3 撤销
- 撤销粒度优先级：`令牌 > 边 > 主体 > 密钥`。
- 撤销后，`epoch` 递增并由 A 签发；主体按周期拉取。
- **撤销生效延迟上界 = 拉取周期**（实测见 E3：周期 10 ⇒ 平均 10 tick）。
  这与 TTL 是两个不同的量：TTL 决定"即使撤销从未被看见，凭证也最多再存活 TTL"。
  v1 把两者混为一谈，此处更正。
- 这是本方案相对中心 PDP 的明确代价：B1 因每次判定都回中心，撤销近似即时生效。

### 3.4 Split-view 检测
两个主体交换 `(epoch, log_head_hash)`。若 `epoch` 相同而 `log_head_hash` 不同 ⇒ 权威等价分歧，置全局告警。此为 v1 缺失的机制。

## 4. 证据平面与漂移检测

输入仅为 `Receipt` 流。检测器特征（全部来自结构化字段，不读自由文本）：
- `deny_rate`：拒绝率 —— **未实现**
- `capability_novelty`：出现过的 capability 相对该主体历史基线的稀有度 —— 已实现
- `resource_novelty`：目标资源稀有度 —— 已实现
- `deny_escalation`：被拒后又去请求"更高"能力的比率 —— 已实现（但含硬编码 +3.0 加项）
- `cross_edge_fanout`：同一 task 下该主体触及的边数 —— **未实现**

判分：对每个特征算稳健 z 分数（中位数/MAD），聚合为 `drift_score`，超阈告警。

**明确声明**：本实现是**确定性统计代理**，用于替换 LLM 漂移检测器以取得可复现性；它不是 LLM 检测器，其 FPR/Recall 不代表 LLM 检测器的表现。论文中三处标注。

## 5. 安全性质 → 机制映射

| 性质 | 类型 | 由什么保证 | 前置假设 |
|---|---|---|---|
| **P1 授权包含**：执行的动作 ∈ 其**单令牌范围**（原表述〔令牌链交集〕强于被检验的命题，已收窄） | 定理 | §2.3 衰减代数 + §3.2 步骤 5 | PEP 未被攻破；世界模型副作用只经 §3.2 步骤 6 |
| **P2 回滚抵抗**：旧 epoch 凭证不被接受 | 定理 | `max_seen_epoch` 单调缓存 | 验证方状态未被回滚 |
| **凭证刷新语义**（差分测试后钉死） | 定理 | 按**链根**解析授权 | 权威保留授权历史 |
| **P3 撤销有界**：撤销后 ≤ `pull_interval + ttl` 内全网不可用 | 定理 | §3.3 | 时钟偏移有界 |
| **P4 归因**：每个被执行的副作用有以接收方签名为终点的事实记录（**归因到边**；〔收据链〕无实现，见 §2.5） | 定理 | §2.5 | 接收方 PEP 未失陷 |
| **P5 传播上界**：被攻破主体的可达**动作集** ⊆ 其合法持有令牌范围并的传递闭包 | 定理 | P1 逐边归纳 | PEP 未失陷 |
| **P5-node**：可达**节点数**有上界 | **假（不成立）** | 无机制 | 实测见 E10：节点半径 = m，无上界；加 `redelegatable=False` 后归零 |
| **P5'**：真实拓扑下该能力并集足够小 ⇒ 实际横向半径小 | **经验命题** | 需实测 | 取决于 scope 过近似程度 |
| 漂移检测的 Precision/Recall/FPR | **经验** | §4 代理检测器 | — |

**凭证刷新语义（差分测试后钉死）**：验证方必须按令牌**链根**解析出该链实际根植的那份授权，
**不得总是使用当前授权**。否则一次常规重签发（`cred_epoch` 递增、链根 id 随之改变）
会让全部在途令牌与用旧根新派生的令牌一并报"链断裂"——参考实现曾如此。

**修复后精确的行为（按实测，勿再按直觉叙述）**：
- **未刷新的对端**：用旧根派生的令牌**仍有效**（链根能解析到旧授权）。修复救活的正是这一类；
- **已刷新的对端**：旧根令牌**仍被拒**，只是原因码由 `TOKEN_INVALID` 变为 `STALE_CREDENTIAL`——
  即回滚防护在起作用，并非"被救活"；
- 因此"未刷新则派生失败"的说法是错的：未刷新时派生**成功**。

配套语义：
1. 未刷新的一方，其旧根令牌仍有效（回滚防护以**验证方已见**的最高 epoch 为准，符合 P2）；
2. 已刷新到新 epoch 的一方，旧根令牌报 `STALE_CREDENTIAL`——**该分支因此可达**
   （差分测试曾实测它在黑盒路径上是死代码）；
3. 刷新必须同时**更新本级持有的根令牌**，否则新旧混用仍会派生失败。

**已删除的断言**：早期版本把 P4 写成「每个被执行的副作用有以接收方签名为终点的**收据链**」。
`Receipt` 无指向父请求或根令牌的字段，全仓库不存在链的构造与校验——该断言从未实现，
现已从规格删除，只作为记录保留在 `paper/review_findings.md` 的局限中。

**P5 是定理（约束能力集合），P5' 是待测命题，P5-node 已被实测证伪。三者不得合并表述。**

**P1/P5 的注意**：其断言路径与判定路径共用谓词（装置自证）。下游锚定是
`src/patterns.py:subsumes` 的 4000 组随机健全性测试与「衰减不放大权限」测试——
它们不是判定路径的代码，且曾抓到一个真实缺陷（`a/**` 被判为 `a/*/**` 的子集）。
引用 P1/P5 时必须同时给出这条锚定。
实测数据见 `results/summary.md` 与 `paper/results_appendix.md`。

## 8. 实验协议（为使主实验可独立复现而补）

**补写说明**：本节是在准备独立复现时补的。此前规格只定义了对象、协议与性质，
**从未定义支柱 B 的主实验**——四级粗化阶梯仅存在于实现代码中，
这意味该实验当时无法从规格复现。本节把协议写到"独立实现应得到可比数字"的精度。

### 8.1 输入

| 项 | 定义 |
|---|---|
| 能力宇宙 `U` | 工具名集合。玩具基底为 18 个手写能力；真实基底为 AgentDojo 某 suite 的 `TOOLS` |
| 委托链 | `A → B → C → D → E`，4 跳 |
| 根授权 `R` | 协调者 A 的根令牌范围，`R ⊆ U` |
| 任务 | 一组需求调用 `(hop, capability, resource)`；真实基底取自某用户任务的 `ground_truth()` |
| 任务→跳的映射 | 真实基底：把 `ground_truth()` 的调用按下标 `i`（**从 0 开始**）分配给第 `i mod 4` 跳（自造规则，登记表已标注）。独立复现指出该处未说明 0/1-based，而两种读法结果不同（合规读法给出 surplus `[0,8,8,12,40]`）；此处钉死为 **0-based**。`resource` 取该调用实参中**首个字符串值**，若无则为空 |
| 下级主体的根授权 | **不参与计算**——第 i(>0) 跳的令牌是第 i−1 跳令牌的衰减，而非下级自身根授权的派生 |

### 8.2 最小必要范围 M

1. 以**宽松范围**（每跳 = `R`）执行任务，记录**实际被放行**的 `(hop, cap, resource)` 轨迹。
2. 第 i 跳的需求 = **本跳自身调用 ∪ 全部下游跳的调用**（因为第 i 跳的令牌是下游令牌的父令牌）。
3. 对每个 `(跳, 能力)`：
   - 若该能力的调用中**存在无资源者**（工具无字符串参数），模式取 `**`（无对象约束）；
   - 否则取该能力全部资源的**最具体公共前缀泛化**：按 `/` 切分，逐段取"全等则字面量、否则 `*`"；
     若各资源段数不一致，取最短长度逐段处理后追加 `**`。
4. `M_i = { f"{cap}@{pat}" }`。
5. **一致性要求**：以 `M` 为逐跳范围重跑任务，必须全部放行。不满足则本实验无效。

### 8.3 四级粗化算子

对 `M_i` 逐条施加，得到 `S_i`，随后**逐跳过滤到 ⊆ 上一级**（第 0 跳过滤到 ⊆ `R`）以保证衰减合法。

**`L4` 是常量算子（第三轮差分测试后钉死）**：`S_i = R`，**与 `M_i` 的内容无关**，
因此即使 `M_i = ∅` 也有定义（workspace 的 `M2 = M3 = ∅` 触发了此缺口）。
「逐条施加」只适用于 L1–L3。
若按字面把 L4 也理解为逐条施加，则空跳给出 `S_i = ∅`——该读法使 workspace 的
L4 由 93 条 surplus / 20 条危害变为 45 / 10。规格钉死为**常量读法**，并要求 E26 报告两读法。

| 级别 | 语义 | 算子 |
|---|---|---|
| `L0_exact` | 精确（上界） | 恒等 |
| `L1_family` | 对象族放宽 | 把模式的最后一段换成 `*`；**若模式已含 `**` 则取 `**`**（放宽只允许变宽，不得收窄） |
| `L2_drop_object` | 丢掉对象约束 | 去掉 `@` 后的模式，即 `cap@**` |
| `L3_over_verb` | 动词过泛 | `L0` ∪ `{ adj@pat : adj 与 cap 的**锚定参数名**相同 }`，`pat` 同原授权。`adj` 的取值范围是**该基底的 `U`**，不是工具库中的全部工具（第三轮差分测试指出此前未说明）。**锚定参数名 = 提取后参数表中的第一个**（`Depends(...)` 参数在提取阶段已排除）；**若 `cap` 无参数则无相邻项**。独立复现指出规格未定义〔非环境参数〕，并给出另一种可辩护读法（首个类型含 `str` 的参数）；该差异使 banking 的 L3 surplus 从 1 变 8、危害从 0 变 4，因此 **E26 必须同时报告两种读法** |
| `L4_no_derivation` | 无推导 | `R` 的全部能力，模式 `**` |

> `L1` 的"不得收窄"是硬性要求：早期实现对已是 `**` 的模式做"末段换 `*`"，把它收窄成
> 只能匹配单段资源，导致任务失败。粗化只允许放宽（spec §2.15）。

### 8.4 度量

| 指标 | 定义 |
|---|---|
| 任务成功率 | 以 `S` 为逐跳范围时被放行的调用数 / 总调用数 |
| surplus 授权 | `S_i` 中不被 `M_i` 包含的授权（按 §2.8 的模式包含判定） |
| 可达半径 | 对每条 surplus `cap@pat`，构造具体资源 `w` 后计 `|{ j : S_j 允许 (cap, w) }|`。**`w` 的构造规则（第三轮差分测试后钉死）**：按 `/` 切分 `pat`，字面量段原样保留、`*` 段与 `**` 的追加段均取固定标记 `probe`；`pat` 为无条件模式时 `w = "probe"` |
| 危害数 | surplus 中能力落在给定危害集合内的条数 |

### 8.5 危害集合的锚定

- 玩具基底：由声明的工具清单（效果类别/可逆性）与数据目录（命名空间分级）计算，
  聚合规则作为 `strict`/`moderate`/`lenient` 三变体穷举（§2.10）。
- 真实基底：取 AgentDojo 各注入任务 `ground_truth()` 所调用的工具集合（**基准自身定义**）。
  注意这是**能力级**集合，与 §2.10 的（能力 × 资源）要求存在已知偏差——真实基底无数据分级目录。

### 8.6 独立复现的最低要求

复现者应**不阅读被复现方的实现代码**，仅依据本规格与公开数据独立实现，并报告：
`M`、各级 surplus 数、各级可达半径、各级危害数、以及 §8.2 第 5 条的一致性检查结果。
